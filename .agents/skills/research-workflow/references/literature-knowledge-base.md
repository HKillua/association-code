# 文献资产与知识库规范

在六技能研究闭环中复用文献、笔记和实验材料。仅在文献入库、知识库建设／问答或增量维护时加载；这里是总控适配层，不新增专业研究技能，不更改源包版本。

## 1. 先确定本轮终点与可用能力

复用已有研究问题、筛选范围、材料目录和本轮终点。区分“找到文献”“保存文献”“完成来源分析”“回答已有资料中的问题”“形成研究方案”，做到用户要求的阶段，不默认每次遍历六技能。

首次涉及外部文献库时检查实际连接能力：条目检索／读取、创建／更新、附件访问，以及用户指定的库和分类。按现有工具说明使用，不从教程字幕猜插件名称、MCP 配置或读写能力。读操作成功不代表写操作可用；不为验证连接擅自删除真实条目。

- 已有可用连接且用户要求入库：按授权范围保存，回读核对条目身份、分类和实际附件，记录返回的定位信息。
- 只能读取或未连接：继续处理可访问的论文／导出文件／本地笔记；需要持久化时形成来源清单或受支持的导入文件，并标明“待导入”。不能声称已写入 Zotero。
- 只需本地笔记：直接使用用户选择的目录。已有项目结构可以作为知识库，不强制搬进新 vault，也不为使用此流程要求安装索引插件或向量库。

技能本身不附带 Zotero 连接，也不自动安装插件、配置服务或启动持续监控；这些工作由对应请求确定。

## 2. 资产分工与保存位置

选择一份可编辑的主要记录，其他位置保留链接或生成视图，避免两份独立笔记互相覆盖：

| 材料 | 推荐归属与交接 |
| --- | --- |
| 文献身份、作者、出版信息、分类、PDF 附件 | 使用 Zotero 时以指定文献库为主要记录；未使用时沿用现有来源清单 |
| 原论文、代码版本、实验日志、数据 | 保留可定位的原件或稳定引用；分析与索引不代替原始证据 |
| 单篇来源分析与 `ANALYSIS_PACKAGE` | `analyze-paper` 的专业产出；可以放在同一篇 Markdown 笔记中，无需再写一份同义摘要 |
| 矩阵、迁移报告、Idea、实验记录、深挖 | 保留各专业技能的正文与包；知识库用 ID、路径和链接关联 |
| 主题索引、阅读队列、工作流状态 | 从上述材料汇总；不在索引中单独维护一套研究结论 |

先映射现有路径。新建知识库且用户要求保存时，可按实际需要采用以下目录；不必一次建齐空目录：

```text
notes/papers/       来源分析与阅读笔记
notes/matrices/     Mode C 证据矩阵
notes/transfers/    条件性迁移分析
notes/ideas/        研究假设与计划版本
notes/experiments/  实验记录及深挖，链接原始运行证据
index/             来源映射、主题入口和工作流索引
templates/         实际使用的笔记模板
```

现有 `papers/`、`docs/`、`research/` 或其他目录均可复用。Obsidian 只需要可读的笔记呈现；专业包若另存为 JSON／YAML，则从笔记引用它，更新时只维护一份事实正文。

## 3. 检索、去重与分层阅读

按问题检索并记录实际查询、日期、来源渠道及纳入／排除依据。明确用户指定论文优先处理；未指定时先根据相关性和证据缺口筛选，再深入关键来源，避免把批量下载等同于批量精读。发现与既有判断冲突的论文时保留冲突及适用条件。

来源映射按“研究来源身份＋具体版本”定位，优先复用已有 `source_id`：

| 信息 | 记录规则 |
| --- | --- |
| `source_id` | 项目内稳定 ID；不要只依靠可能重名或改名的标题／文件名 |
| `identifiers` | 已核实的 DOI、arXiv ID、正式 URL 等；未核实不补造 |
| `source_version` | 实际使用的论文版本／日期／代码提交；无法确定就记未知，可用已读取文件的哈希辅助辨识 |
| `zotero_locator` | 可选，记录连接上下文、库类型／库标识、条目 key、附件 key；不能把孤立 item key 当作跨库唯一身份 |
| `source_path_or_url` | 本轮实际访问的原件；远程存在不等于本机已下载 |
| `fulltext_status` | 已核验可访问全文／仅摘要／获取失败／尚未检查，记录失败原因 |
| `read_coverage` | 实际读过的摘要、章节、图表、附录或全文；PDF 已下载不等于全文已读 |
| `analysis_refs` | 现有笔记路径、包 ID／版本；未分析可为空 |

这些字段属于来源清单或总控补充层，可沿用等价字段，不必复制到每份专业包。包级证据状态仍使用原契约的含义，不能用“下载成功”替代 `verified`。

去重和恢复规则：

1. 优先按标准标识匹配，标题＋作者＋年份仅用于候选核对。不同版本或预印本与正式发表版本核验后关联，保留版本差异；不按标题近似自动合并。
2. 同一来源、同一版本已有充分分析且本轮问题未变时复用；新增问题只补相关证据。版本不明时不假定相同。
3. 批量任务按条目记录实际保存与分析结果。写入超时或结果不明时先查询是否已成功，再决定重试，避免重复建条目；同一原因持续失败时保留具体失败项，不无边界重试整批。
4. 仅摘要的来源可作为明确标注的来源主张或待查线索；缺少方法、实验或全文定位时不得编造对应结论。后续矩阵保留它的阅读边界，不能升级为直接机制证据。

## 4. 阅读笔记与证据交接

`analyze-paper` 决定专业分析内容；模板只提供统一的导航与保存形式。需要继续研究设计时沿用原契约的完整 `ANALYSIS_PACKAGE`，不能用几项摘要字段替代它。已有合格分析只补映射，不为套模板重读或重写。

笔记至少让读者区分：

- 研究问题与适用条件；作者如何做、实际报告了什么。
- 关键主张、支撑证据及定位；方法细节和实验结果不能脱离版本与条件。
- 作者声明的局限、分析者推断的局限，以及尚未获得的证据。
- 与当前研究的关系、待核问题及关联包；研究联想仍为推断，不冒充正式 Idea。

关键论断引用链为：`论断 → source_id + source_version → 页码／章节／图表／公式／代码或日志位置`。笔记内部链接帮助导航，不能替代原始证据定位。论文页码与 PDF 页序不同则注明；原文无页码可用章节、表号等实际存在的定位，不虚构页码。

原有 `SC/DE/AI/UN` 与包级 `verified/partial/unknown` 分开保留。不要把“作者解释为某机制”升级为“直接证明机制”；引用同一原始证据的多篇笔记也不增加独立证据数量。自有实验事实仍须经过记录与深挖后进入 Mode C。

使用 Obsidian 属性时只添加检索所需的少量标量／列表，如来源 ID、阅读覆盖、包 ID 和标签；复杂矩阵和证据映射留在正文或原包中。属性不是证据，也不表示完成了人工复核。用户批注保留在明确的独立区域；未知归属的旧内容先保留，必要时另存修订版。

## 5. 基于知识库的问答

问答不强制经过 Mode C。仅当用户要求构建问题—现象—机制关系或继续设计研究时，才交给专业阶段。

1. **确定证据范围。** 复用用户指定的笔记／来源／实验范围。明确“仅笔记”时不静默引入外部资料；允许回溯已链接原件时检查相关证据。缺口可在答复中提出，不把建议的检索当成已经执行。
2. **检索实际内容。** 从现有索引、来源 ID、主题词及同义词找到候选，读取相关正文和证据位置。按问题、方法、条件搜索，并查找反例；不能只读标题或索引摘要。材料较多时分批处理，说明实际覆盖范围；没有充分覆盖不得声称全库无证据。
3. **区分证据层次。** 只核对了笔记就表述为“笔记记载”；访问原文并核对具体位置后才称原文已核实。比较不同论文时说明数据、评价协议和条件差异，不直接把异质结果排成可靠优劣榜。
4. **回答并定位。** 关键结论就近链接实际读取的笔记／原件及位置，区分来源主张、直接观察、推断和未知。存在矛盾时陈述两侧证据；未检索到只表示本轮范围内未找到，不表示文献或现象不存在。
5. **交付或回流。** 交付结论、依据、覆盖边界和关键缺口。要求保存时才更新待补证据项；需要研究设计的缺口先进入 Mode C，用户只问问题时就在问答结束。

索引插件仅用于组织和展示；不能由“有索引”推定模型已检索或读完全部笔记。向量检索若已有可用于召回，命中的内容仍需阅读核对；没有向量库也可以使用文件检索完成本轮任务。

## 6. 增量维护与完成标准

维护 `source_id + source_version → analysis_id → matrix_id → idea_id → experiment_id → squeeze_id` 的已有依赖。保存迁移包时按契约补入相关链路；历史实验仍可无 Idea 直接入链。

- **新论文／实质版本变更：** 比较相关差异，保存新分析版本；将受影响的矩阵和计划标记为待复核，记录原因。待复核是索引状态，不自动将原包的证据状态全部改成未知。
- **仅元数据或路径变化：** 修正定位，不无故重做研究分析。
- **新真实实验：** `record-experiment → squeeze-experiment → deep-read` 增量回流；日志不能直接变成新的 Idea。
- **重生成笔记：** 保留原始证据、人工批注和历史分析，只修改明确由代理维护的部分。原分析与当前理解冲突时保存修订依据，不静默改写过去的结论。

首次建立流程时可用少量用户相关来源验证：每个入库结果能找到真实条目／文件，关键论断能定位证据，重复处理能复用既有成果，仅摘要材料被正确标注，资料不足的问题会给出有边界的回答。验证已授权的实际操作即可，不为测试额外创建或删除用户资料。

报告实际完成、复用、部分完成和失败项及原因，并给出对下一阶段有判别力的补证据步骤；不要用“任务已结束”代替逐项完成情况。
