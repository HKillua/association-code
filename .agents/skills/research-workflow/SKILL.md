# 六技能研究总控

协调六个专门技能，让证据、假设、适配方案和实验事实有明确的交接关系，按用户当前阶段推进研究。

五个原有技能适用于通用研究；`transfer-ml-methods` 仅在 AI／机器学习研究需要跨领域方法迁移时加入。它提供机制匹配与适配研究，`discover-innovation` 负责统一研究假设、价值判断和最终验证计划。

文献资产与知识库层负责收集、保存、检索和增量维护；六个专业技能负责研究分析。Zotero、Obsidian 和索引插件按现有环境选用，不是启动研究的前提。

## 1. 确定本轮范围与入口

从用户请求、已有笔记、论文版本、代码、实验记录与项目约定确定：目标任务、当前材料、要回答的问题、本轮终点、评价协议和资源限制。已有信息直接复用；只澄清会改变决策的缺口。

| 当前材料与目的 | 进入阶段 | 交付与后续 |
| --- | --- | --- |
| 需要检索、筛选或整理文献 | 文献资产层，调用可用的检索技能／工具 | 带筛选依据的来源清单；要求入库时保存并核验，按本轮需要选文进入分析 |
| 新论文／协议／代码，需要理解来源 | `analyze-paper` | 来源分析；继续研究设计时生成 `ANALYSIS_PACKAGE` |
| 已有笔记，需要带依据的回答或比较 | 知识库证据问答 | 检索实际内容、核对引用和适用条件后回答；仅需问答时不强制建矩阵 |
| 多来源或已有现象，需要建立问题与机制联系 | `deep-read`，仅 Mode C | `MODE_C_PACKAGE`，保留 P/F/M/E 与连接点 |
| 有证据连接点，需要设计研究 | `discover-innovation` | `IDEA_PACKAGE`；跨领域 ML 方案进入迁移分支 |
| 明确要迁移某个 ML 方法，或寻找其他领域解决同一困难的方法 | `transfer-ml-methods` | 判断或迁移方案；正式研究计划交回 `discover-innovation` |
| 已有真实运行／研究证据，需要记录 | `record-experiment` | `EXPERIMENT_RECORD`；没有 Idea 包也允许记录事实 |
| 已有实验记录，需要诊断机制／异质性／稳健性 | `squeeze-experiment` | `SQUEEZE_REPORT`；新增知识回流到 Mode C |

存在可核验的等价交接材料时，补齐关键字段后复用，不因格式不同重做阅读。尚未执行的方案不能进入真实实验深挖。历史实验可以从记录阶段进入，不倒写“事先计划”。

## 2. 加载实际需要的技能

根据入口读取当前阶段对应的 `SKILL.md`，遵循其方法与产出边界。优先使用用户指定路径，其次使用当前可用技能目录中的路径；需要查找时检查相邻技能目录及 `~/.agents/skills`、`~/.codex/skills`。同名副本优先使用已选版本，不混读不同版本。

只加载当前阶段和下一次交接所需的内容。技能不可用时明确记录缺失，继续不依赖它的工作；不要声称已调用。总控负责路由与交接，不替代六个技能的专业分析，也不授权额外外部操作。

需要交接包、正式研究方案或多轮推进时读取 [六技能交接契约](references/six-skill-contract.md)。核对旧包或原始规则时读取 [压缩包中的五技能流程](references/original-five-skill-workflow.md)。判断入口与边界时参考 [路由示例](references/routing-examples.md)。

涉及文献入库、批量笔记、Zotero／Obsidian、知识库问答或增量更新时，读取 [文献资产与知识库规范](references/literature-knowledge-base.md)。它规定来源身份、阅读覆盖、保存映射与引用核验，不替代专业技能的产出。只做简短研究判断时不搭建目录或批量迁移材料。

## 3. 主流程与跨领域迁移分支

```text
检索／现有文献库 → 筛选、去重、全文状态 → 研究来源
研究来源 → analyze-paper → ANALYSIS_PACKAGE
                                   ↓
                       deep-read（仅 Mode C）
                                   ↓ MODE_C_PACKAGE
                      选择一个有证据的连接点
                          ┌────────┴────────┐
                 通用研究设计          跨领域 ML 方法迁移
                          │                ↓
                          │      transfer-ml-methods
                          │                ↓ TRANSFER_PACKAGE
                          └────────┬───────┘
                                   ↓
                       discover-innovation
                                   ↓ IDEA_PACKAGE
                    实际执行（按用户授权的范围）
                                   ↓ 原始证据
                        record-experiment
                                   ↓ EXPERIMENT_RECORD
                       squeeze-experiment
                                   ↓ SQUEEZE_REPORT
                        deep-read（增量合并）
                                   ↓
                            下一轮选择连接点
```

要求保存时，将各阶段产出按来源和包 ID 关联到本地笔记与索引；已有等价材料直接映射。知识库问答可从任何已保存阶段进入，沿引用回溯证据。问答发现的缺口先进入待补证据项；需要研究设计时再走 Mode C，不能把问答建议直接当作已验证的 Idea 或实验结果。

迁移分支适合在有目标问题和 Baseline 后启用。进入时复用 Mode C 的问题、现象、机制线索、证据和边界，不重新从零诊断。缺少实测失败案例时，区分文献中的现象与目标任务中尚待验证的现象，可以给条件性方案或诊断计划。

若 `discover-innovation` 的候选筛选发现需要借鉴外领域方法，先交给迁移分支，再回到同一个 Idea 完成设计。用户已指定源方法或已有 Idea 时直接核验该方法／方案，不重新穷尽找候选。单独询问可迁移性可以停在迁移判断；正式研究方案须有可追溯的 Mode C 输入，等价矩阵可以复用，缺失部分按需补齐并标明未知。

迁移分支负责：目标 A 的失败证据；源方法 B 的作用机制与生效条件；已有迁移案例的改造经验；A 到 A′ 的条件适配；A／A′／A′+B 的归因设计。不能只凭输入维度能接上或模块名称相似就认定能迁移。

总控将迁移结果整理为本流程新增的 `TRANSFER_PACKAGE`，保留原报告；不要声称原技能自带这个接口。`discover-innovation` 复用条件表与实验组设计，整合新颖性、研究价值、资源与否证规则，产出一个最终 `IDEA_PACKAGE`。两者不各自生成一份冲突的最终实验计划。

迁移中补读的重要源论文用 `analyze-paper` 分析；新增证据改变问题、现象、机制或连接点时由 `deep-read` 增量更新矩阵。只增加接口或工程细节时更新迁移包与 Idea 版本，避免无信息增量的往返。

## 4. 维护证据与实验归因

- 保留 `SC`（来源主张）、`DE`（直接证据）、`AI`（分析推断）、`UN`（未知）。包级 `verified/partial/unknown` 描述交接材料的证据完整性，不等于假设已被验证。
- 文献可获取、实际阅读覆盖和证据状态分别记录。关键论断关联具体来源版本及可定位证据；仅摘要或局部阅读不能写为全文精读。重复笔记和同源转述不计作独立证据。
- Mode C 的 `C` 是连接点，迁移技能的 `C` 是已有迁移案例。在交接中分别命名为 `connection_C_id` 和 `transfer_case_ids`。
- 迁移方案区分原始 Baseline A、仅条件适配 A′、适配后加方法 A′+B；测量条件是否建立、目标现象是否改善、机制预测是否出现、整体效果与成本。额外对照按竞争解释选择。
- 记录所有真实运行、排除和执行偏差。一次性能改善不能单独证明机制；源领域成功不能代替目标任务实验。
- 实验新发现先经 `squeeze-experiment` 梳理，再回到 Mode C；不能将报告直接改写为下一轮 Idea。

## 5. 推进、停止与交付

按用户授权和本轮终点继续必要阶段；用户只要判断或方案时在该阶段交付。协调技能本身不自动启动训练、改动模型、消耗付费计算或实施研究操作；用户已明确要求相应执行时无需再次确认已有授权。

每次迭代只深入一个主连接点。出现新证据、有区分力的检验或重要条件冲突时更新；若只是在重复推测，交付当前判断与最小补证据步骤。无法建立迁移条件或代价不合适时可暂缓候选，不强行拼接模块。

交付包含当前判断及依据、已完成阶段、相关交接包或路径、关键未知项、下一步及其判别作用。按用户所需深度呈现，不为短问答输出全部模板。用户要求持久化或项目约定需要时保存包与索引，使用版本或追加方式保留历史。

入库或批量阅读还应交代实际完成、复用、部分完成及失败的条目；接口返回成功后核验目标内容，不能把待导入清单称为已入库。更新来源时只复核受影响的产出，保留人工批注与旧版本。未连接外部工具时继续处理可访问材料，准确说明尚未完成的外部操作。
