# Squeeze Experiment — 通用实验数据深挖

## 0. 在五 skill 流水线中的位置

本 skill 是证据增值层，消费一个或多个 `EXPERIMENT_RECORD` 及其原始证据，生成 `SQUEEZE_REPORT`。它负责找出结果背后的动态、机制线索、异质性、稳健性和新现象；新发现随后回流到 `deep-read` Mode C。

```text
EXPERIMENT_RECORD(s) + 原始证据
              ↓
      squeeze-experiment
              ↓ SQUEEZE_REPORT
      deep-read（Mode C 增量合并）
```

## 适用范围

本 skill 适用于计算机训练/评估、数值模拟、实验室实验、材料与工程测试、临床或行为研究、田野观察、调查、A/B 测试、设计研究和混合方法研究。它不预设 AUC、loss、GPU、特征空间、样本类型或某个学科的成功阈值。

核心思想是：一个实验的主要结果只回答一个问题，原始数据、过程记录、失败案例、异常值、子组差异和不确定性通常还能回答更多问题。分析目标不是强行证明方案有效，而是最大化可复核的信息产出。

## 前置读取与配置

先读取能够建立证据链的材料：

- 实验计划、假设、预注册、协议或研究问题
- 实验记录、版本、配置、原始日志和数据字典
- 对照组、基线、历史结果和预先指定的主要结果
- 代码、分析脚本、仪器设置、样品批次、操作者和环境记录（如有）
- 已有知识库，检查发现是否重复、矛盾或需要修正

先声明：

```text
实验/研究名称：{名称}
研究问题与主要假设：{问题}
实验单位/样本/材料：{对象}
主要结果与估计目标：{指标或质性目标}
对照与基线：{对照}
数据、日志和代码位置：{路径}
本次分析的资源边界：{时间/算力/样本/伦理限制}
输入实验记录：{EXPERIMENT_RECORD ID/路径，可为多个}
```

路径、日志或数据不存在时，列为缺失证据，不要用默认值补全。若实验涉及人、动物、敏感数据、生物安全、危险设备或隐私信息，先遵守相应审批、脱敏和访问规则。

## 2A. EXPERIMENT_RECORD 输入契约

开始深挖前，至少读取：

```text
experiment_id
source_idea_id / plan_version
execution_status
research_question_and_hypothesis
planned_vs_actual_design_and_controls
actual_configuration
samples_materials_or_data_provenance
all_runs_or_repetitions
results_with_uncertainty
observations_and_deviations
evidence_locations
known_limits_and_missing_evidence
```

缺失字段必须进入“事实与证据边界”，不能从最终结果反推出实验配置。若分析多个实验，先分别核对每个 `experiment_id`，再做跨实验综合。

## 证据与结论规则

1. 先确认数据和过程完整，再解释结果。
2. 报告点估计时同时报告样本量、重复、区间、变异或其他不确定性。
3. 区分统计显著、实际/临床/工程意义、机制证据和可复现性。
4. 结果不理想不等于假设被排除；说明当前设置下观察到的范围、可能原因和能区分原因的后续测试。
5. 任何新发现都要能回到原始数据、日志、图表、样本、代码或操作记录。
6. 一个诊断脚本、统计检验或图表尽量只回答一个明确问题；共享的特征/数据提取与具体分析分开保存。
7. 不因多次切分、指标或子组分析而挑选最好的结果；记录探索性分析，并说明多重比较或选择偏差风险。

## 总体工作流

```text
Step 1  建立实验事实表与数据血缘
   ↓
Step 2  解释主要结果与不确定性
   ↓
Step 3  检查过程/收敛/时间/批次/资源动态（如适用）
   ↓
Step 4  机制与中间量诊断
   ↓
Step 5  错误、异质性与边界条件
   ↓
Step 6  稳健性、敏感性和替代解释
   ↓
Step 7  知识沉淀与下一步决策
```

每一步都先判断“本实验是否有相应数据”。没有就跳过并注明原因，不为了填模板而捏造分析。

## Step 1：建立实验事实表

| 项目 | 要提取的内容 |
|:--|:--|
| 身份与版本 | 实验名、日期、代码/设备/协议版本、操作者 |
| 设计 | 实验单位、样本/材料、组别、随机化、盲法、重复、排除规则 |
| 干预/输入 | 改变了什么，保持了什么，剂量/参数/时间/环境是什么 |
| 结果 | 主要结果、次要结果、原始单位、聚合方式、区间/误差 |
| 过程 | 运行时长、训练/反应/测量轨迹、异常、停止规则 |
| 资源 | 数据量、算力、仪器、批次、成本、失败的运行 |
| 证据位置 | 文件、表图、日志行、样本编号、脚本或仪器记录 |

检查数据血缘：原始数据 → 清洗/预处理 → 中间数据 → 分析 → 图表/结论。记录任何不可逆处理、手工筛选、缺失值、异常值、数据泄漏和标签/编码变化。

## Step 2：解释主要结果

先回答主要问题，再分类结果：

| 观察 | 应回答的重点 |
|:--|:--|
| 结果高于/优于基线 | 增益大小、区间、跨重复一致性、是否有实际意义、是否可能来自预算/调参/泄漏 |
| 结果接近基线 | 等效性或不确定性范围、检测能力、是否存在子组或机制层面的差异 |
| 结果低于/劣于基线 | 差异从何时出现、是否由设置/实现/资源/样本造成、哪些机制仍可能存在 |
| 结果波动大 | 重复间变异、批次/操作者/设备/随机种子、测量可靠性 |
| 主要指标无变化 | 次要结果、中间量、成本、速度、稳定性或安全性是否变化 |

必须检查：差异是否在所有重复、时间点、数据切分或样本中一致；结论是否依赖最佳一次运行；置信区间/可信区间是否足以支持“有差异”“无重要差异”或“证据不足”。

## Step 3：过程、动态与收敛

按研究类型选择：

### 计算/训练/模拟

- 指标、目标函数、学习率/步长、资源消耗和验证结果随时间的轨迹
- 早期与后期差异、过拟合、发散、梯度/数值范围、随机种子和 checkpoint
- 训练目标与最终评价之间是否解耦

### 实验室/工程/设备

- 温度、压力、剂量、时间、批次、校准、漂移、仪器饱和和故障
- 反应/性能曲线、稳态与瞬态、重复性、滞后和疲劳

### 临床/行为/田野/调查

- 随访/时间趋势、依从性、失访、干预暴露、操作者或地点差异
- 测量重复性、编码者一致性、问卷完成模式和时间效应

记录“何时开始分叉”以及最可能的替代解释。不要把过程轨迹中的相关变化直接解释为因果。

## Step 4：机制与中间量诊断

从输入到主要结果画出机制链：

```text
输入/干预 → 中间状态/过程 → 测量 → 主要结果 → 决策/应用
```

对每个箭头问：

- 是否有直接观测，而不是只看最终结果？
- 中间量是否可靠、是否受处理影响、是否可能是碰撞指标或后处理产物？
- 是否存在机制竞争、补偿、饱和、阈值、延迟或反馈？
- 哪个测量能区分“机制真的变化”与“评价方式/噪声变化”？

按数据类型选择工具：分层/混合模型、时间序列、灵敏度、消融、反事实/中介分析、显微/谱学/传感器读数、编码主题、用户行为或其他领域合适的方法。工具必须服从研究问题，不要为了使用某种方法而强行添加分析。

## Step 5：错误、异质性与边界条件

### 5a. 错误模式

对有预测或分类输出的研究，分别检查误报、漏报、边界样本、校准、不同阈值和代价敏感性。对没有预测输出的研究，检查异常样本、测量失败、协议偏离和质性反例。

### 5b. 子组和异质性

按预先有依据的维度分解：人群、材料、场景、类别、设备、批次、时间、环境、任务难度、数据质量或暴露程度。报告每个子组的样本量和不确定性，避免只挑表现最好的分组。

### 5c. 边界条件

明确方法/现象何时不成立、性能何时下降、资源阈值在哪里、是否存在分布外样本或公平性差异。这些结果常常比整体平均值更能指导下一项实验。

## Step 6：稳健性、敏感性与替代解释

选择与本实验风险匹配的检查：

- 不同随机种子、重复、批次、操作者、设备、实验日或数据切分
- 预处理、阈值、超参数、模型/统计规格、缺失值、异常值和聚合方式敏感性
- 阴性对照、安慰剂、伪标签/置乱、时间错位、负控或已知标准样本
- 与简单基线、强基线、替代测量或外部数据的比较
- 复现原始主要结果所需的最小条件

对于高成本分析，先做风险排序：优先处理最可能改变结论且成本最低的替代解释。结果保持不变时记录“对该因素稳健”；结果改变时记录“结论依赖该因素”，不要隐藏。

## Step 7：知识沉淀与下一步

将发现分为：

| 类型 | 内容 |
|:--|:--|
| 已回答 | 由哪些数据直接支持，适用范围是什么 |
| 新现象 | 可重复、定量或有清晰质性证据的规律 |
| 新限制 | 当前设置下暴露的边界、混杂或失败模式 |
| 未决问题 | 仍缺的观测、对照或样本 |
| 方法改进 | 下一次只改变什么，如何区分多个解释 |
| 可复现性 | 代码、数据、协议、环境和随机性是否足够复核 |

只有在用户要求持久化或项目约定要求时修改文档。追加时保留历史、日期、来源和证据位置；不要直接覆盖旧结论。若一个新发现尚未得到独立重复，标记为“待复验/探索性”。

## 与其他 skill 的衔接

```text
IDEA_PACKAGE → 实际执行研究
                    ↓
              record-experiment
                    ↓ EXPERIMENT_RECORD
              squeeze-experiment
                    ↓ SQUEEZE_REPORT
              deep-read Mode C
                    ↓ MODE_C_PACKAGE
              discover-innovation（下一轮）
```

即使报告中已经出现了明确的下一步想法，也先把新 P/F/M/E 放入 Mode C；不得跳过证据整合层直接生成下一轮 Idea。

## 禁止行为

- 不只抄录一个总指标就结束分析。
- 不把探索性子组、最佳运行或后验调参包装成预先验证的主结果。
- 不把相关的中间量当作已证明的机制。
- 不忽略失败运行、异常值、缺失数据、批次差异、数据泄漏和测量误差。
- 不因结果低于预期就直接给出“方向没有价值”的结论；先提取当前设置下的限制、证据和可区分的后续测试。
- 不在没有访问原始数据、日志、代码或实验记录时声称完成了诊断。
