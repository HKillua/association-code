# 入口与路由示例

以下是流程设计例子，不是真实研究结果，也不证明某个方法可迁移。

## 1. MTAD 航迹关联与融合，尚未建立自己的 Baseline

用户希望沿用 TMTAFF 利用数据集的思路，借鉴其他领域方法。

先用 `analyze-paper` 核对任务构造、标签、输入时序、融合参考和评价协议，区分论文已报告内容与复现缺口。再用 Mode C 整合论文限制与目标问题。没有自己的错误样本时，“关联置信度不可靠使融合误差扩大”只能是候选机制，不能当作已观察到的根因。

明确要跨领域借鉴时，用 `transfer-ml-methods` 条件性地考察匹配、滤波等领域的具体源方法。核实监督、概率解释、噪声或状态定义等生效条件，再由 `discover-innovation` 形成一个诊断／pilot 计划，优先区分误匹配、坐标预处理、标签构造或融合实现等竞争解释。尚未有实验时停在设计，不生成实验结论。

## 2. 用户指定源方法，已有任务与机制矩阵

例如“评估把某个图匹配方法迁移到当前关联 Baseline”。直接进入迁移技能，复用矩阵，核验具体论文与版本。判断源方法条件能否在 A 中建立，设计 A／A′／A′+B 对照。只问可迁移性就在此交付；要求研究计划再交给 `discover-innovation` 更新同一个 Idea。无需重读无关文献。

## 3. 总指标涨了，但只看了一次运行

先用 `record-experiment` 收集真实组别、预算、数据划分、选择规则与所有运行；未提供的不猜测。完整记录已有时复用。再用 `squeeze-experiment` 分析收益是否来自适配、额外容量、预算或源机制，回流到 Mode C，标注机制未知。没有 A′ 对照时记录归因缺口并提出补做设计，不能声称已证明 B 有效。

## 4. 普通论文问题或非 ML 研究

“这篇论文的公式表示什么”使用来源分析或直接回答，不运行全部六个。“分析实验室研究并设计后续复验”可走原五技能流程；未涉及 AI／机器学习方法迁移时跳过迁移技能，不强加模型模板。

## 5. 真实实验没有事先 Idea

从记录阶段进入，`source_idea_id: none`，记录已知事实与缺口，再深挖、回流。不能为满足流水线而事后制造预先注册的预测。

## 6. 两个 C 与旧包字段不同

Mode C 的 `C03` 是问题—现象连接；案例论文用 `transfer_case_ids`，不引用 `C03` 充当案例。记录包分别写了 `research_question` 与 `hypothesis` 时，为深挖建立字段映射，不将真实字段差异判成材料不存在。

## 7. 检索文献、保存 Zotero，并生成 Obsidian 笔记

先读取文献资产规范，复用研究范围，检查实际连接和目标路径；筛选并核对来源身份、版本和全文状态。已有充分分析直接复用，新材料由 `analyze-paper` 处理，保存时关联来源与包。两篇仅有摘要时分别标注局部阅读，不能将整批报告为全文精读。Zotero 不可写时继续处理本地材料并交付待导入项，不能称入库已完成。用户只要求笔记就在此结束，不强制产生创新方案。

## 8. 只根据已有笔记回答跨论文问题

例如“仅根据 notes，哪些证据支持异步采样导致关联错误？”检索并读取相关笔记，核对条件、反例和已有来源定位，只能称已核实笔记内容。不能为了补齐结论静默联网，也不能把一篇论文在三份笔记中的转述算作三项独立证据。证据不足就指出缺口；仅问答不必生成 Mode C 包。

## 9. 论文新版本改变了关键实验结果

关联到同一来源的具体新版本，保留旧分析和人工批注，补读实际变化部分；更新分析并在索引中标记受影响矩阵／Idea 待复核。若只是文件改名，修复路径即可。用户要求继续研究时增量更新相应阶段，不以一次论文更新为由重跑所有技能或启动训练。
