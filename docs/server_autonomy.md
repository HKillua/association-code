# 服务器现场执行规则

职责、并发上限和授权原则见[AGENTS](../AGENTS.md)；当前任务、前置、次数和预算只认[交接索引](../HandOver/Handover.md)。用户已取消逐次批准；本地AI确定具体实验并发布READY，服务器按交接执行，不自行扩展范围。

## 可自主处理

- 复用现有环境／数据，修正仓库外路径、缓存、同版本依赖和传输；优先处理具体故障，不重复安装、smoke或准备已成功数据。
- 在最多四个已发布并领取的单卡作业内按实验室FIFO选兼容GPU，允许共卡及预算内换卡；按UUID绑定，进程内cuda:0是逻辑编号，不终止他人进程。换卡不重置尝试次数或额度。
- 限制CPU／OMP／MKL线程、调整日志缓冲；使用独立冻结checkout和全新输出目录，活动目录不pull，主仓可提交回执。

## 托管、墙时与失败

用户要求任务脱离远程AI／网络后继续。使用服务器已有服务管理器或调度器托管一次性作业；入口为`tools/experiments/launch_detached.py`。systemd用户服务须确认管理器持续存在（如Linger=yes）、服务与AI运行时进程组分离、Restart=no，独立日志和真实退出码落盘。nohup／setsid不足以证明能抵抗整组回收，不静默降级。

新任务launcher与训练CLI显式`--time-policy advisory`。全部准备、等待、训练、评价、写盘与清理计入实际耗时；超建议时长写`time_advisory.json`并报告进度／剩余成本，继续固定任务、不加步，不再询问批准。离线不保证即时通知；旧hard接口仅为兼容，不改活动冻结时限。真实故障和用户停止指令仍执行。

提交成功只代表SUBMITTED。重连后读取实际output／record-dir及同一服务状态，不重新拼简化任务名；文件未找到先核路径，不当作仍在运行。通用launcher不负责后继调度，服务验证和实际命令按当前L2S。

2026-10-25用户要求睡前排队，本批新增一次性的096—097有限队列，具体范围见[L2S夜间交接](../HandOver/L2S-20261025-096-097-night.md)。仅固定三项GPU和四项CPU，不是永久守护；由一个CPU systemd服务统一持有接续权，不与手工领取并行。统计本仓全部GPU launcher领取、等待原服务释放、排除仍被占位UUID和他人compute进程；失败只阻断相关下游，不重试，整批终态后退出。新队列发布与托管仍需真实回执，不能因代码或计划存在而写已启动。

确定代码错误、OOM、非有限数值或数据损坏时保全现场并按本轮失败流程结束；不缩模型／batch、改精度、删样本或放宽验收续跑。模型、loss、采样、数据／标签、归一化、指标／选模、测试使用及训练量均保持本轮协议；后续修复或新实验由本地AI另行发布具体交接，不再等待用户批准。一次尝试失败不自动重试，不能覆盖原失败记录。

## 回传

独立S2L记录实际命令、起止／累计耗时、设备／共卡、退出码、完成更新／阶段、配置偏差、指标和原件路径；缺失写明，不补造成功。只提交必要小型聚合及逐场证据，省略内容明确登记；完整预测、权重和日志留服务器。回传main不改变冻结运行目录，结案整理遵守AGENTS，活动／未审回执保留。
