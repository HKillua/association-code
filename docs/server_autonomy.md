# 服务器现场自主权与本地研究责任

生效：2026-10-16；GPU及本地定时跟进授权更新：2026-10-17。用户直接授权不固定某张卡、允许与他人共卡，以能够执行任务为准；该授权优先于旧 ENV-004/005 文档与示例中的“只用空闲卡／禁止共卡”限制。此规则适用于当前及后续交接；每轮仍须给出具体任务、资源和总预算，服务器不因一般授权自行启动未下发的实验。

原则：**本地决定研究做什么、什么结果算有效；服务器决定如何在既定约束内把任务可靠地执行完。**发生现场问题时，服务器先诊断并在授权内修复，向本地回传证据与结果，不把普通网络/路径/资源问题逐项交给用户处理。

## 取消SHA准入与验收（2026-10-17，用户直接指示）

本地与服务器都不再以SHA、hash、fingerprint或精确提交匹配判断能否启动、复用或验收。新命令不含SHA检查，程序不因历史hash缺失/变化拒绝已有产物。旧回执/历史请求保留原文，此项用户指示优先于其中的旧要求；不要新增SHA取证任务。

Git正常同步并保护已有修改；任务运行中不改它的执行代码。完成状态、真实配置、角色/种子、划分场景、文件可读性、数组形状/标签和实际指标仍须核对。保留路径、命令、退出码及失败现场；版本和旧hash可作为已有元数据，无须补齐或判别。训练中用于固定随机种子/原划分的hash运算不属于SHA判别，不改变这些研究算法。

## 本地应用定时仓库跟进（2026-10-17）

用户授权本地Codex应用定时检查（当前每6小时） `association-code` 的仓库更新，应用自动化ID为 `mtad`。本地可同步并审阅索引、回执与证据，自主分析常规问题、修复和测试后提交推送，推进既定计划内有明确范围、预算和验收条件的诊断及后续交接。恢复既定行为的代码缺陷、路径/日志/包装器和证据校验修复均可自主处理，不因触及代码就转为重大决策；仍须记录原因、验证结果和实际执行命令和配置。

重大决策再问用户：改变研究目标、候选方法/对照，改变采样与数据覆盖/划分、标签、指标/选模或冻结测试集的使用，改变研究依赖版本约束/精度策略，明显扩大总训练规模或已批准预算。应先形成具体可审阅方案；常规诊断和修复不逐项请求批准。每轮原有尝试次数与累计deadline仍有效，不能通过定时触发或新文件给旧任务续期。

RUNNING期间，本地可以读取仓库更新、在隔离分支修复测试，不修改活动任务的已下发L2S或对方S2L，不开启同一条线的下一轮。服务器保持已领取的执行代码和本轮预算不变。用户2026-10-18要求baseline与候选并行：另一条线有独立批准预算与READY即可推进，不要求活动线先取得好分数；最多两个单卡作业。若会发布不同执行代码，先明确独立checkout/worktree，活动任务不pull改变文件；未明确隔离时不向main推执行代码/配置变更。并行不扩大任何一项预算。终态回执到达或双方明确取消后，本地可自主提交常规修复并按既定计划新建交接；重大方案变更仍由用户决定。纯文档更新可改变HEAD，但不能改变被冻结的执行文件、活动任务语义或历史文件归属。

这项授权限于本地应用跟进仓库，不包含SSH值守服务器、轮询服务器日志、向其他线程发消息，或在服务器安装后台守护/定时监控。服务器仍在已领取任务的预算内前台监督执行，仓库推送本身不会唤醒另一个AI。各自L2S/S2L的归属、已下发文件不可改写、索引同步和保留失败证据的规则继续生效。

## 现场处置必须留下的证据

每次处理写入自己的同一份 `S2L-*.md`：症状与时间、诊断证据、采取的操作、保持不变的版本/研究约束、操作前后结果、尝试编号、累计耗时及剩余预算、文件/包装器/环境来源和路径。无需每一步先发消息等本地答复。

GPU 回执记录实际型号、UUID、剩余显存/利用率、共卡情况及各次候选与失败原因。共卡竞争可能影响耗时和可用显存；区分本进程峰值分配与整卡占用，不将本轮测量作为独占性能 benchmark。

小型日志、freeze、检查 JSON、现场包装器可作为本轮证据提交到 `HandOver/results/<run_id>/`；凭据、环境变量全集、数据、权重和大日志不提交。包装器只是现场证据，不自动成为下轮规范执行代码；需要复用的修复由本地审阅后纳入 `tools/setup/`。

网络恢复不等于 CPU 测试通过，CPU 通过不等于 CUDA 已验证，合成 smoke 通过不等于正式模型能训练或研究假设成立。回执分别报告这些状态。

## ENV-004 的授权实例（历史；GPU 限制已由 2026-10-17 授权覆盖）

- 当时按 FIFO 等待空闲卡最多 20 分钟、检查间隔不少于 60 秒；这是历史规则，当前不再因已有他人 compute 进程而等待或拒绝启动。前台有界监督、不建后台自动化的边界继续有效。
- CPU 总计 15 分钟、CUDA 执行总计 10 分钟，均包括失败尝试、现场修复和终止宽限；CPU 与 CUDA 各最多两次尝试（每阶段至多一次补跑，不是重跑完整流程）。等待预算另外最多 20 分钟。第二次必须针对已定位并处理的临时故障，成功阶段不重跑；CUDA 补跑可引用同代码下已成功的 CPU attempt。
- 每阶段首次开始即记录不可重置的截止时间，第二次仅使用剩余额度，阶段间不挪用预算。GPU 等待按累计等待时间计算，不能通过再次进入等待而重新获得 20 分钟。截止后只做必要终止和证据归档，不再启动执行。
- 本地负责本轮测试语义修复；服务器不能自己把失败断言放宽。CUDA 未过之前不进入真实 MTAD prepare/profile/训练。
