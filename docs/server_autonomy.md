# 服务器现场自主权与本地研究责任

生效：2026-10-16。依据：用户要求给服务器 AI 一定授权，并由本地确定必须控制的事项与可交由现场处理的问题。此规则适用于当前及后续交接；每轮仍须给出具体任务、资源和总预算，授权不自动启动新实验。

原则：**本地决定研究做什么、什么结果算有效；服务器决定如何在既定约束内把任务可靠地执行完。**发生现场问题时，服务器先诊断并在授权内修复，向本地回传证据与结果，不把普通网络/路径/资源问题逐项交给用户处理。

## 责任表

| 事项 | 决策方 | 服务器可做的事与边界 |
|---|---|---|
| 研究目标、候选方法、对照组、科学结论 | 本地 | 提供实测现象、诊断建议，不自行改方案或宣布优于论文 |
| 模型、损失、训练逻辑、数据生成与清洗、划分、标签、归一化、评价和选模 | 本地 | 按冻结代码运行；缺失材料或发现缺陷时保存最小复现，不用临时替代实现继续正式实验 |
| 测试断言、容差、跳过测试、成功标准 | 本地 | 可以定位故障、收集数值差异；不能修改容差、禁用测试或把非零退出当成功 |
| Python/NumPy/PyTorch/CUDA 构建版本约束、AMP/TF32/确定性策略 | 本地 | 保持交接 pin 和精度策略。普通依赖由解析器解析并满足 pip check，完整 freeze 回传；改变研究依赖版本或计算精度须本地决定 |
| 下载、DNS/IPv4、包缓存和镜像 | 服务器 | 可探测连通性、在本进程/本项目 venv 限定 IPv4、使用官方源和清华 TUNA 镜像、重用已校验文件、使用支持续传的下载方式；保持 TLS 校验与包来源记录，不手列依赖绕过解析器 |
| 虚拟环境修复和同版本安装 | 服务器 | 优先验证/复用已成功环境，允许在预算内修复本轮环境或新建独立 venv；保留旧环境及证据。不得修改系统驱动、全局 DNS、系统 Python 或其他用户环境 |
| 数据路径、存储与输出目录 | 服务器 | 查找本任务已有文件、核验大小/hash、修正仓库外路径映射、创建唯一输出目录；不重新生成/替换数据、删除失败证据、覆盖已有 run |
| GPU 分配和等待 | 服务器 | 按实验室 FIFO 在本轮允许数量内选择/换用空闲同类设备，按 UUID 绑定，启动前复核；不得抢占。可在交接明确的等待预算内主动等待并观察，未给等待预算则直接回传卡忙；不建后台守护/定时轮询 |
| CPU 线程和运行包装器 | 服务器 | 可在不改变训练语义的前提下限制 OMP/MKL 线程、调整日志缓冲、设置设备可见性，记录实际值；可写仓库外包装器，不能覆盖仓库脚本或设置隐藏的算法开关 |
| 超时、断流、暂时资源不足 | 服务器 | 有明确原因和修复动作时按本轮允许次数重试，所有尝试计入原预算；新输出保留失败。确定性代码/测试失败停止，不能反复碰运气 |
| OOM、NaN、持续非有限梯度、损坏数据 | 本地决定研究变更 | 服务器停止本次进程、保留现场。若证实 OOM 来自其他进程占用，可在原配置及预算内换空闲同类卡重试；模型本身容量不足或数值错误则回传。不能擅自减 batch/序列长度、开混合精度、跳样本或降低模型规模 |
| 进程与日志管理 | 服务器 | 监督本轮、采集日志和资源，优雅结束或按预算杀掉可证明属于本轮的进程树；不按进程名批量杀 Python，不触碰他人任务 |
| 场景数、种子、epochs、总时间/GPU 数/重试上限 | 本地或用户 | 服务器负责分配执行次序、使用剩余预算，不自行扩预算。用户现场直接新增授权时记录后执行，仍不伪造研究成功 |

## 现场处置必须留下的证据

每次处理写入自己的同一份 `S2L-*.md`：症状与时间、诊断证据、采取的操作、保持不变的版本/研究约束、操作前后结果、尝试编号、累计耗时及剩余预算、文件/包装器/环境来源与哈希。无需每一步先发消息等本地答复。

小型日志、freeze、检查 JSON、现场包装器可作为本轮证据提交到 `HandOver/results/<run_id>/`；凭据、环境变量全集、数据、权重和大日志不提交。包装器只是现场证据，不自动成为下轮规范执行代码；需要复用的修复由本地审阅后纳入 `tools/setup/`。

网络恢复不等于 CPU 测试通过，CPU 通过不等于 CUDA 已验证，合成 smoke 通过不等于正式模型能训练或研究假设成立。回执分别报告这些状态。

## 当前 ENV-004 的授权实例

- 直接复用 FIELD 已安装的 Python 3.11.7 / NumPy 1.26.4 / torch 2.5.1+cu121 环境，重新验收当前代码。原 ENV-003 失败保持不变。
- 若路径、导入来源、同 pin 依赖存在现场问题，可在 CPU 阶段总预算内诊断修复；先保存环境现状。不得重试确定性测试失败。
- GPU 忙时允许服务器在本轮最多等待 20 分钟，检查间隔不少于 60 秒，并遵循 FIFO；全部忙且预算用尽则回传 partial。这里是当前任务内的前台监督，不是后台自动化。
- CPU 总计 15 分钟、CUDA 执行总计 10 分钟，均包括失败尝试、现场修复和终止宽限；CPU 与 CUDA 各最多两次尝试（每阶段至多一次补跑，不是重跑完整流程）。等待预算另外最多 20 分钟。第二次必须针对已定位并处理的临时故障，成功阶段不重跑；CUDA 补跑可引用同代码下已成功的 CPU attempt。
- 每阶段首次开始即记录不可重置的截止时间，第二次仅使用剩余额度，阶段间不挪用预算。GPU 等待按累计等待时间计算，不能通过再次进入等待而重新获得 20 分钟。截止后只做必要终止和证据归档，不再启动执行。
- 本地负责本轮测试语义修复；服务器不能自己把失败断言放宽。CUDA 未过之前不进入真实 MTAD prepare/profile/训练。

因此，这次 IPv6、镜像、缓存、同 pin 环境恢复交给服务器；测试语义由本地修复；GPU 选择与有界等待交给服务器；正式模型和数据实验的下一阶段由本地根据回执决定。
