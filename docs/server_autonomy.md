# 服务器执行与本地研究职责

当前任务、前置和额度只认[交接索引](../HandOver/Handover.md)。本地决定研究方案和结果解释，服务器在已批准条件内负责可靠执行。普通网络、路径、设备、日志问题自行处理，回传操作及结果。

## 可自主处理

- 复用现有环境和数据；修正仓库外路径、缓存、同版本依赖与传输。优先处理具体故障，不重复安装、smoke或准备已成功数据。
- 动态选择兼容GPU，允许共卡；按UUID绑定，进程内cuda:0是逻辑编号。用户2026-10-22明确并发上限为四个获批单卡作业，按可用GPU与实验室FIFO调度，不再限制为两个；在此上限内调度已获批任务无需重复申请并发许可，不终止或暂停他人进程。
- 限制CPU/OMP/MKL线程、调整日志缓冲、在已明确的次数和总预算内调度。没有全局默认重试数，换卡不重置次数或额度。
- 使用独立冻结checkout执行；活动目录不pull改代码，主仓可以提交回执。新输出不得覆盖既有run。

## 断开后继续训练

用户已明确要求任务脱离远程AI/网络连接继续。正式任务使用服务器已有服务管理器或调度器托管一次性作业；本仓入口是`tools/experiments/launch_detached.py`。

systemd用户服务须核实用户管理器持续存在（如Linger=yes）、服务与AI运行时进程组分离、Restart=no，独立日志和真实退出码落盘。用户最新选择建议时长：新任务launcher和训练CLI均显式`--time-policy advisory`，不按墙时杀训练，超过建议时长只写`time_advisory.json`并提示。AI检查后说明进度/剩余成本并询问；离线不能保证即时通知，等待期间继续当前固定工作、不追加更新或实验。旧hard接口仅作兼容，活动任务不通过改文件变更冻结时限。停止信号与真实故障仍只清理本组。普通nohup/setsid不能证明能抵抗运行时整组回收，不静默降级。

提交成功只代表SUBMITTED。AI可断开，重连后读同一服务/结果，再领取满足前置的下一任务；没有自动队列守护。服务验证、预算和实际命令见当前L2S，不从本页推导新实验授权。

监督读取直接使用实际提交保存的输出目录及record-dir，不重新拼接简化任务名；首次读不到状态时先核路径和服务记录，不把“文件不存在”当作仍在训练继续空等。039—041曾因仓库外监视脚本漏掉`-attempt-1`造成回报延迟，训练本身正常；本规则修正路径使用，不增建监控服务或自动重试。

## 必须保持与停止条件

- 模型、损失、采样、数据划分/标签、归一化、指标/选模、测试使用、依赖精度和训练量按已批方案。核心研究改变、新实验/重复次数/训练量或付费资源增加先交具体方案；超过建议时长询问用户，不自动停止。
- 确定代码错误、OOM、非有限数值、数据损坏时保存现场并按本轮失败流程结束。不缩模型/batch、改精度、删样本或放宽验收来继续。只有当轮明确允许才可重试；以当前L2S的具体预算与尝试次数为准。
- 准备、选卡/等待、训练、评价、写盘、失败和清理均计入实际累计耗时。超过建议时长先询问，不自动终止；结束轮次不重开，失败不自动重试。新实验、更新量、尝试次数、超出已批并发上限或付费资源增加仍需具体方案与用户决定。
- Git仅协作与历史追溯，不设置SHA/hash/fingerprint门槛。核实际配置、划分、数组/标签、命令、退出码及完成状态；原划分的确定性排序算法不因取消门槛而改变。

## 回传与维护

回传独立S2L：实际命令、起止/累计耗时、设备和共卡情况、退出码、完成更新与阶段、配置偏差、指标及产物路径。缺失写明，不补造成功。小型证据放`HandOver/results/<run_id>/`；数据、权重和大预测留服务器，避免将重复全量快照提交进仓库。

用户已授权结案后将旧交接和冗余产物总结后从工作树删除；Git历史保留证据。这不授权修改未审回执或删除服务器正在使用的runs数据。当前活跃/未审材料保留。

本地每6小时跟进仓库，常规修复必要检查后可commit/push；不SSH值守、不建常驻监控、不跨聊天或向外部人员发消息。push不会唤醒服务器。无变化安静，有实质结果、失败、交接或需用户决定时再通知。研究与清理准则见[AGENTS](../AGENTS.md)。
