# 共同局部时间窗：首版讨论方案

2026-10-19。状态：**DRAFT_DISCUSSION_ONLY**。本文仅供一次研究决策讨论，未实施、未改变执行配置、未获新增GPU预算，不发布READY；017保持原样。此前批准的候选表示与结构实现，不包含本次时间任务修改。

## 为什么提出

TMTAFF确实要求在统一的 `Tstart–Tend` 内补全首尾并使用长度64，但没有公开可还原的窗口秒数、步长或最大补全跨度。[外部处理核验](../../results/external_mtad_processing20261019/README.md)支持“当前整场景Q64与其他公开协议有实质差异”，不证明它是确定解析bug。已有3固定V场景中，单片段约32%的合法query距自身支撑超过30分钟；该比例不能推广至全库。

建议将下一次baseline与候选的**主比较**明确为共同局部窗，原整场景远距离任务保留为独立压力测试。下面数值全是待批准的首版工程假设，不是作者参数、已证最优值或真实耗时估计。

### 别人通常怎样限定时间

本项目已核论文中有三种不同用法：CA-LSTM先取两轨时间交集、对齐后用10–50点滑窗；PTFM对已关联双源轨迹的共同覆盖段做对齐/切窗融合。MH-T2TA/CIAG用60秒关联窗，但不承担整套缺失补全和融合。TSA-cTFER最多128点、超长可留最近点、每20秒在线关联。TMTAFF最接近我们的三环节目标：预定共同时间范围、补首尾、长度64，但未给出确切窗长。逐篇出处见[已核处理对照](../../results/external_mtad_processing20261019/README.md)；原文页码与本地全文位置记录在其所列研究证据目录。

因此，“限定共同时间任务”有参考依据，**“必须21分钟”没有公认标准或作者参数支持**。下述1260秒只是将64个query设为间隔20秒时得到的候选，并非由旧时间编码单位推导出的必然选择。用户追问文献惯例不构成对这套数值或任务变更的批准；本方案继续待讨论。不能直接照搬仅交集匹配的做法而取消我们的首尾缺失恢复。

## 一套具体规则

| 项目 | 推荐规则 |
| --- | --- |
| 查询时刻 | 每窗64点：`q[j] = start + 20*j`，`j=0..63`，首末跨度1260秒（约21分钟） |
| 步长 | 相邻起点相差640秒，约半窗重叠 |
| 起点 | 对场景所有**原先有效片段的真实观测时刻**取最小值 `t_min`，首窗起点为 `20*floor(t_min/20)`；不使用reference、标签时间或误差选起点 |
| 末窗 | 起点依次加640秒，直到当前窗末时刻已覆盖观测最大值 `t_max` 即停止；不足一窗仍保留完整64点，不挪末窗、不拉伸查询间隔。超出reference实际时间的点继续按原规则无真值，不补造监督 |
| 三环节 | 同一窗内所有轨迹共享这64个绝对查询时刻；TCM/TAM/TFM及候选四臂均遵循同一时间契约 |
| 首尾缺失 | 自然缺失与既有端点遮挡都在该共同窗内定义；不另设10分钟loss裁切。按到最近真实输入的距离报告0–5、5–10、>10分钟层次 |

**20秒在这里拟用于实际query间隔。** 以前的 `time_unit_seconds=20` 只是时间编码缩放，原全场景linspace实际间隔随场景变化；它不是原传感器统一采样周期。原生观测时刻仍不量化、不重采样，编码单位仍与query间隔分开记录。

### 保留短轨，允许明确的离线上下文

- 原片段的真实首末支撑与窗口相交即纳入；不因短、单点落窗、无参考监督或模型误差而删除。所有原先有效短轨至少归入一个窗口，并以原scene/fragment ID计数核对，窗口副本不算新原轨。
- 输入先取窗内真实点。若不足2个，从**同一原片段**补入距离窗口最近的真实点直至2个，距离相同按时间先后；不得从其他轨迹或reference补点。一个原本有效片段已有至少2个不同真实时刻，故无需制造观测。
- 这是**离线允许窗外上下文**，不声称在线/因果预测；窗外上下文可早于或晚于查询窗。其时刻原样保留，记录数量及距离，且不改变本窗公共query。它也意味着极端内部长缺口仍可能存在，不能声称所有输入都已局限在21分钟以内。
- 先按窗口选择原始有效观测，再沿既有均匀索引规则cap128；不能先对整条长轨cap128再切窗，避免原本窗内有点却被全轨抽稀抹掉。原CSV、原身份及片段ID不修改。参考offset、gap600及逐属性mask沿用；600秒不是本方案窗口的文献依据。
- 窗口完全没有真实观测及相交有效片段时不构造模型样本；有输入但没有可评真值的窗口仍保留并报告，不能按reference可用性筛窗。原场景完全无有效输入的情况单独登记，不用标签时刻发明窗口或从人口账中消失。

## 划分与采样：先选源场景，再选窗

所有窗口继承原源场景划分与共享身份隔离，T_test继续封存。对同窗保留轨迹仍按原身份定义正负候选，不按新得分或reference可用性改标签；不共窗的跨时段轨迹对属于另报的长时任务，不假装已评价。

首版采用最简单的两级随机采样：沿用每批正负各半；**每个类别先均匀选一个含该类候选的原训练场景，再均匀选该场景含该类候选的窗口，最后按原规则选该类pair**。仅正对训练阶段用对应的正类分支。没有该类pair的窗不参加该类抽样，但保留在数据账与完整窗口评价；不是要求每个窗口都有正例，也不从reference可评性重抽样。

不把全部窗平铺后均匀抽，否则长场景会因窗口多获得更高训练权重。首版不额外加逆频率loss权重：半窗重叠会让部分轨迹和pair多次出现，两级采样只控制场景权重，**不保证原轨/pair等权或与旧分布相同**。这项变化必须随本方案一起批准并披露；保留所有输入也不等于有限随机更新会遍历每条短轨。训练量、选模和预算随后写入统一执行方案，不能借“窗口更多”自行增加更新数。

## 结果怎么报，避免把更窄的任务包装成全场景成功

主表比较同一窗口协议的baseline、候选及四臂。为避免重叠窗数量支配宏指标，先在同一源场景内聚合窗口，再按源场景汇总；同时保留原轨/身份覆盖、窗口副本计数、无输入/无监督人口、完整可评点与共同点结果。窗口身份阈值如何选及物理重复点如何计数须写进后续正式配置，未批准前不套旧阈值或产生新主排名。

长时间接续、跨窗身份一致性、远期外推仍用原任务独立报告，历史结果保留。**局部窗口的结果不能直接拼成原全场景指标**：跨窗合并和重复预测裁决尚未定义，本方案不增加这套全局系统，也不声称已解决完整长时任务。新旧主表不直接相减归因创新；先看同窗baseline与候选是否学会基本恢复、关联和辅助融合。

只增加“最大监督外推跨度”不是推荐替代：它只屏蔽loss，整场景输出仍可能进入关联/融合，且全范围评价包含失去直接监督的远点。现阶段可先对已有预测按支撑距离分层用于分析，不产生新训练任务。
