# TCM问题与机制证据

本页只维护跨实验的机制判断，逐轮数值见[分析索引](README.md)，当前任务见[交接索引](../../../HandOver/Handover.md)。033增训有效但补全未通过；036短程反馈不足以确诊主要故障；037圆周表示在途。候选034/038已完成，不能将其decoder现象直接套用到baseline。

Baseline真正可比的是020 TCM1000与033 TCM4000：同协议、同seed的独立训练，前1000步并非逐位一致，不是连续训练的两个快照。031/032/034是另一套物理teacher，028为收尾、029/030/036/038为零训练诊断；历史过程不再重复列举。

## 1. 训练量确实影响了结果，但不是全部答案

共同四场1671/2056/290/113、86片段，目标、分母、normalizer及state-hold控制逐片段一致：

| 指标，128维特征MSE | 1000步 | 4000步 | 下降 |
| --- | ---: | ---: | ---: |
| 原生双向一步 | .00829482 | .00640866 | 22.74% |
| 实际自然query | .00628511 | .00527430 | 16.08% |
| 支撑外query | .00887771 | .00718965 | 19.01% |

训练唯一片段覆盖69.10%→99.07%，但4000步仍只相当于4.67次名义轨迹呈现，不是4000个epoch，也不等于已经收敛。不能继续说“loss平台说明训练量没用”。

033完整V64/1635片段中，自然query均值比state-hold低21.71%，但858条更好、670条更差、107条相同。107条全部没有可评支撑外query，只经过共同插值，不能记作TCM成功。**41.0%的片段差于保持，失败尚多。**

训练日志进一步排除一个错误方向：020/033 TCM均**没有触发clip1**，裁剪前最大梯度范数约.3903。031/032候选每步裁剪的事实不能搬过来解释baseline。033后面三个千步窗口中，最大1%的batch贡献约22.10%/20.83%/20.22%的loss总量；均值受长尾批次影响，中位数继续下降。日志缺少这些batch的身份和分属性损失，不能把尖峰直接归因于某一来源或航向。

## 2. 已定位的结构性问题

### A. 学习目标和我们要求的“补齐”不是同一件事

当前`completion_loss`只学习**本传感器原生观测序列的下一条embedding**，目标detach，输入投影冻结；没有reference位置或自然query目标参与。评价一步时仍使用原生观测，而评价自然query时换为reference。

这带来三个具体后果：

1. 训练得更像下一条带噪量测，不等于去掉来源偏移、恢复无偏轨迹。9002场景共同偏移应由有可辨识信息的跨源配准处理，不能全部要求单轨TCM凭空消除。
2. 当前补全流程只在支撑外使用TCM的学习输出，训练仍是原生一步预测。**支撑内query直接使用观测插值，两轮其误差完全相同**；若抱怨中间插值或量测偏差，单纯增加TCM预训练步数不会改变这部分输出。
3. 一步到自然query同时改变了目标来源、时间跨度、encoder可用历史和预测反馈。501条“一步优于保持、query差于保持”证明一步指标不足以验收补齐，但不能单独证明递推反馈就是根因。

这是直接代码事实及评价事实。原论文Eq13本身也是观测embedding预测，故不能把它说成抄错论文的确定bug；实际任务适配与完整下游训练仍需单独检验。

### B. 训练监督约一分钟后的一步，应用递推覆盖半小时以上

从固定T_core512/V64的公共`scene_contract`复算：

| 输入任务统计 | 结果 |
| --- | ---: |
| T_core每片段平均相邻native间隔的中位数 | 55.17秒 |
| V每片段平均相邻native间隔的中位数 | 75.29秒 |
| V共同query窗口中位数 | 7149.5秒，约119.2分钟 |
| V支撑外query距对应端点的中位数 | 1953.22秒，约32.55分钟 |
| 上述端点距离的95分位 | 5179.38秒，约86.32分钟 |
| 每片段支撑前/后递推步数的中位数 | 25/21步；两侧最大均62步 |

间隔是**先求每片段平均再取中位**，不是所有相邻点间隔的中位数；外推距离包括缺reference的查询，描述任务难度而非可评点误差。这些数不能相除当成严格难度倍数。

时距、反馈、缺少观测带来的不确定性是不同问题。短native多步监督即使有效，也不自动解决半小时到一小时的恢复。不能擅自删远点、缩窗或声称论文SL64就表示21分钟；作者实际窗口尚未核明。

### C. 现有特征几何让总MSE不适合单独验收位置

030在同四场86片段重建冻结输入投影，state-hold与保存评价吻合。原生相邻状态zscore变化平方量中：

- 航向占**93.08%**，经纬度合计仅**0.0318%**；
- 2511个原生相邻对中，513个原始航向差超过180°；按圆周最短差处理，航向变化平方量减少38.29%；
- 只改变时间编码的特征MSE为.015568，同目标时刻state-hold误差为.011116，前者约为后者1.40倍。

例如359°和1°相差2°，线性航向却呈现358°跳变。全局坐标标准化又会压小相邻位置变化。这些是现有输入/目标几何的直接证据，**不是“93%的训练loss或梯度来自航向”**；ReLU、投影和时间交叉项也使上面几项不能相加成贡献比例。

`state + PE4`先混合再投影，decoder另接PE128，提示状态与时间重建纠缠，但尚未证明是主因。当前输入投影冻结不会自行重整这种几何；直接解冻又可能让预测目标一起塌缩，不能无保护解冻后宣称修好了。

### D. 短轨保留了，损失却主要由长轨的预测项组成

TCM均匀抽轨，loss按全部`2*(n−1)*d`预测元素求平均。全训练库的静态组成如下：

| native点数 | 片段占比 | 相邻点监督项占比 |
| --- | ---: | ---: |
| 2—4 | 7.93% | 0.387% |
| 5—15 | 24.80% | 5.233% |
| 16—31 | 21.90% | 11.573% |
| 32—63 | 21.56% | 23.112% |
| 64—128 | 23.80% | 59.694% |

这是全库监督项的数量比例，**不是实际SGD累计梯度贡献**；每个batch分母不同。抽样覆盖与均匀抽轨相符，没有发现采样器漏短轨。V中2—15点轨占41.35%，训练集为32.73%，短轨问题在评价里更突出。

033的2—4点159条轨，一步只有80胜79负，自然query81胜78负；一步加权误差相对保持下降16.69%，弱于其余长度组。可是64—128点165条轨，一步161胜4负，自然query仍有59条失败、33条仅共同插值。**短轨弱是一个问题，不能解释长轨的一步到实际补齐落差。** 不据此删除短轨或把训练改成只看长轨。

## 3. 候选与下一步的边界

候选032/034消去学习部分的时间变化几乎不改误差，034航向仍差于观测控制；038已在decoder内定位幅度逐层衰减。它们不证明033的latent也塌成常量，亦不证明loss冲突。当前[039—041](../../specs/cooperative-decoder-ablations.md)独立检验decoder归一化顺序、深度和teacher身份目标，以完整V误差而非activation幅度验收。

保留033作为原参考端点，035验证其关联用途；037以相同4000步单独检验圆周航向表示，无自动TAM。新旧latent MSE不可跨空间排名。短轨归一化、短程free-running、运动底座等仍是后续候选，不因本页讨论自动加目标、改权重或启动实验。校准与时间补全分开；真值对应oracle不作方法成绩。

## 4. 已查与未查的边界

- 源码审查未发现next-time重复、逆向忘翻时间、因果mask泄漏、padding或支撑内mask清零的新错误。state-hold已按目标时间重新embedding，控制没有沿用错误旧时间编码。
- 冻结输入与detach目标是明示设计，不是漏训参数。论文把投影写为可训练，需披露差异，但不据此直接解冻。
- 原文p5§2.1、p6§2.2声明时空配准；p16实验预处理未给配准算法、未知对应估计、是否真值辅助或配准后误差。因此只是尚未核明的复现细节，不能断言作者已消除9002共同平移。
- 论文没有独立TCM米误差。当前特征MSE、候选物理MAE与论文融合指标不能直接混排。
- 所有结果是已暴露开发数据、单seed证据；没有多种子、独立最终测试或统计显著性结论。真正的下一训练方案仍须由可区分原因的结果决定。

本轮纠正的是问题定位和评价解释；**没有发现并宣称修复一个足以解释全部低分的代码bug，也没有将尚未验证的训练改法写成成功。**
