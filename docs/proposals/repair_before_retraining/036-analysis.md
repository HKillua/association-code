# 036结果：短程反馈有代价，但不是当前已证实的主要故障

2026-10-20；`SQUEEZE_REPORT`。输入为[036服务器回执](../../../HandOver/S2L-20261020-036.md)、run/launcher记录及完整逐片段`reference-feedback.json.gz`；关联[TCM综合排查](tcm-diagnosis.md)中的反馈假设。**本次削弱“先加短程free-running训练就能解决大部分补齐失败”的依据，没有排除长时距递推问题，也没有证明表示问题是唯一根因。**

## 1. 实验有效，先确认测的是什么

冻结033的TCM4000端点，同normalizer、同目标时间、同初始prefix encoder memory。oracle在每步预测结束后回填该步真实native embedding，free回填自己的预测；两者都不增加encoder memory。state-hold使用初始prefix端点物理状态，在各目标时间重新embedding。目标是原生量测而非reference。

原4场1671/2056/290/113、86片段全部保留，其中82条可评、4条n=2不足以留出目标，仍在结果中。3条n=4只有前两步，因此h1/h2各164个双向目标，h3为158个；特征维度128。164个方向首步完全一致，结合执行代码核查支持本次反馈对照成立。逐片段SSE/分母重新加总与服务器全部方向、步数聚合一致。

退出0；payload墙时12.553秒、launcher墙时16.935秒，不能称GPU kernel累计时间。无训练更新、无reference CSV读取、无normalizer重拟合、无margin/阈值重选，T_test封存。本地仅复算已返回数据，未加载真实权重或再次推理。

## 2. 主要结果：第三步出现小幅代价，第二步并不一致变差

以下均是**128维特征MSE，没有米或角度单位**；变化率为`free/oracle−1`，正值表示使用预测反馈更差。

| 预测步 | 双向目标数 | 真实历史反馈 oracle | 自身预测反馈 free | 端点保持 | free相对oracle |
| --- | ---: | ---: | ---: | ---: | ---: |
| h1 | 164 | .005945700 | .005945700 | .009440110 | 0 |
| h2 | 164 | .005633740 | .005604749 | .009638127 | −0.515% |
| h3 | 158 | .005887443 | .006141168 | .010640231 | +4.310% |
| 只合并h2+h3 | 322 | .005758228 | .005867960 | .010129842 | +1.906% |

h3若改用真实历史，相对free误差下降4.13%；这只是**此冻结模型的输入反馈对照效果**，不是多步训练收益的理论上限。free在h3仍比端点保持低42.28%，说明它在这个短原生预测任务上有平均收益，并非一递推就失灵。

不能把h2/h3的变化归结为不同人口：只保留79条三个目标都可评的轨，h2的free仍比oracle低0.721%，h3仍高4.310%。不过两个步数的目标点和时距仍不同，不能把h1→h3总MSE当成纯反馈误差累积曲线。

## 3. 不能只看平均：有一致方向，也有反例

| 场景 | h2 free相对oracle | h3 free相对oracle |
| --- | ---: | ---: |
| 1671 | +12.01% | +2.87% |
| 2056 | −4.17% | +5.11% |
| 290 | −1.57% | +4.53% |
| 113 | −2.08% | +3.14% |

h3四场均变差，不是一个异常场景制造的结果；前向+3.50%、反向+5.00%。但是1671在h2已有12.01%的代价，其余三场h2反而改善；不能说反馈损害处处都小，也不能说每一步都单调恶化。

只合并有反馈差异的h2/h3：

- 按片段合并双向误差，47/82条free更差、35条更好；不是普遍恶化。
- 按来源，9001的free比oracle高4.06%，9002反而低0.46%；这是描述性分层，不能推断来源噪声的因果机制。
- oracle和free各有30/82条差于保持，其中28条是共同失败。**即使每步都给真实历史，许多基础预测失败仍在。**

oracle只是“预测后提供真实量测历史”的对照，不是误差必然最低的数学oracle。真实量测可能带噪，固定模型对不同反馈也可能有不同响应；本次没有分离这两种解释，不能据此声称free在主动降噪。

## 4. 这次能排除什么，不能排除什么

本次h1/h2/h3到初始prefix端点的时距中位分别约65.58/150.5/232秒；h3范围47.86—1064秒，中位约3.87分钟。此前完整V自然query的支撑外端点距离中位约1953秒、95分位5179秒，且实际有数十步递推。两组统计人口和目标不同，只用于说明覆盖范围，不能直接相减归因。

因此，本次支持：

1. **短原生时距内确有反馈影响，但未显示巨大、普遍、逐步爆炸的误差。**
2. 原先501条“一步好、自然query坏”不能简单归因反馈累积；target由量测换reference、长期时距、固定上下文和特征几何仍未分离。
3. 仅补真实历史也未解决28条共同失败，短程反馈纠正不是充分解法。

本次不能证明：

- 长达半小时以上或20—60步的反馈安全；
- 原TCM已学会物理位置、速度和圆周航向恢复；
- 圆周航向、属性尺度或时间编码就是低分的唯一原因；
- 加入多步训练无效，或其收益上限只有4.13%；
- 036结果能推广到完整V、独立测试集或所有随机种子。四场开发数据已多次暴露，相关片段不是独立重复。

## 5. 对下一步的实际调整

**不据036立刻给TCM加free-running loss，也不再单纯增加原TCM步数。** 将短程多步训练保留为后续同预算对照，降低它作为首选修复的优先级；这是研究决策，不是把该方法判无效。

baseline继续保留033，已启动035按原计划训练TAM。035验证补齐特征对关联是否有用；无论它涨分与否，都不等于TCM物理补齐验收。

下一项TCM改进设计应优先回应**已有直接证据的表示与任务问题**：圆周航向的线性跳变、位置局部变化在当前几何中很弱、时间编码与状态混合，以及短监督时距与长query需求的差别。若进入新训练，建议先做单一圆周航向表示对照，不同时换位置坐标、时间编码、loss与采样；该变体属于研究改进，保留033近似参考。由于表示空间改变，新旧latent MSE不能直接排名，需要共同的下游关联/物理结果。这里只确定优先设计方向，**没有生成新训练READY或改动在途034/035**。

候选034仍按已批准航向观测残差方案运行；它和baseline TCM表示对照是不同问题。候选位置/速度动态近常量与跨源校准仍沿原独立证据处理，不把036当成这些问题已解决。
