## 建议时长的行为约定

新任务在launcher和训练CLI两层均显式使用`--time-policy advisory`。`max_seconds/max_hours`保留正有限数值，含义改为建议时长；不使用null、无穷或巨大数字绕过检查。systemd不设运行硬截止，worker超建议时长只写一次`time_advisory.json`和stderr提醒，继续当前固定工作。AI检查时说明已耗、完成进度、预计剩余时间和风险，再询问继续或停止；等待期间不自动杀任务，也不增加更新/新实验。AI离线时只有落盘提醒，不能保证即时发问。

默认`hard`兼容历史实验。真实异常、OOM、非有限值和手动停止仍正常结束并保留原件；第一次SIGTERM后忽略重复SIGTERM，避免中断终态清理，外层清理grace/SIGKILL仍有效。不新增常驻通知平台。

**正在跑的020/021已经读入旧时限。** 修改Git文件不会改变活进程，不宣称已取消它们的截止，也不为此停训重开。020旧服务约北京时间10月20日14:47截止；021 attempt3约10月19日19:26，进程内14400秒可能更早触发。接近截止仍未完成时，服务器报告实际阶段与检查点，由用户决定；不注入进程内存。
