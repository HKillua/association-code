# ENV-005：按执行契约复用 CPU 验收，解除纯回执提交对 CUDA 的误拦

日期：2026-10-16。来源：用户要求修复 ENV-004 的整仓 HEAD 相等检查，以及拉取 `6ea92a6` 后的本地证据审计。本轮复用 FIELD 环境，只做 CPU 复验与单卡合成 CUDA 验收，不启动真实 MTAD 数据准备、profile 或训练。

## 已知事实与判断

1. ENV-004 的 CPU 阶段一次通过，耗时 32 秒：95 项 tests、15 项旧审计、依赖与导入检查通过；CUDA 未执行。此次修复前，回执中 39 个 manifest 文件的哈希与拉取后的对应文件一致。
2. 纯 `HandOver/` 回执提交改变了 HEAD，旧 CUDA 入口要求其与 CPU 记录的 SHA 完全相同，因此继续执行会在 GPU 操作前误拦（本轮没有实际启动 CUDA，此处是源码确认的后续限制）。应验证执行文件与环境是否相同，同时保留两个 SHA 的来源记录；不要求 CPU 与 CUDA 之间禁止提交回执。
3. 等待日志包含 18 个采样，跨度 1167 秒，样本中的 `free_cards` 均为空；其中两个间隔为 19 秒、20 秒。因此，回执所述“全部间隔 75 秒／至少 60 秒”不成立。离散采样也不能证明四小时内从未出现空档。
4. CUDA 尚无运行证据，“smoke 显存小于 1 GB”不能作为实测结论，也不能据此使用已有他人进程的 GPU。旧回执与失败证据保留，本地审计另行说明差异。
5. ENV-004 缺少新契约要求的受检字段的 `environment.json`。即使旧源码哈希一致，也不能直接迁移为新契约下的 CPU 成功凭据；ENV-005 首次必须重新执行 CPU 验收并生成快照。

## 修改与验收规格

| 条件 | 修改/输出 | 验证 |
|---|---|---|
| 只有交接回执变化，执行代码与环境不变 | CPU/CUDA 共用 `tools/setup/verification_contract.py`，允许实际 SHA 不同；分别记录 CPU 来源 SHA 与当前执行 SHA | 纯回执提交后可通过复用检查；保留提交溯源 |
| 执行源码被修改、新增或删除 | helper 统一枚举执行文件集合并比较路径与内容哈希，不只检查旧 manifest 中已有文件，也不把 39 写成固定数量 | 修改、新增、删除分别拒绝；未跟踪的执行文件也纳入检查 |
| 解释器、依赖或执行环境发生变化 | CPU 保存执行环境字段快照，CUDA 启动前重新采集并按同一 schema 比较；不能仅比较 NumPy/PyTorch pin | 环境差异拒绝复用，明确报告拒绝原因；不得静默降级到旧检查 |
| 本项目 editable 的 freeze 随文档提交改变 HEAD | 仅当安装元数据的 Name、editable 标记与 direct_url 真实目录确认是本仓库时，规范化为真实路径、项目名与安装版本；其他依赖的 VCS pin 保留 | 真实服务器格式的 editable 行随 HEAD 改变允许；外部 SHA、项目版本变化拒绝 |
| CPU 凭据缺失、不完整或失败 | 校验阶段完成状态、退出码、源码 manifest 与环境快照；缺字段或不支持的 schema 明确拒绝 | ENV-004 旧凭据、缺快照、失败或损坏凭据均不能放行 |
| 首次建立新契约凭据 | 在已有 FIELD 环境执行 CPU 复验，生成新的 `source_files.json`、`environment.json` 和成功凭据 | 本轮 CPU 成功后才可进入 CUDA；不凭旧回执叙述补造快照 |
| 当前轮次与 CPU 来源不同 | driver 独立接收当前 `run_id`、CPU 来源 `run_id` 及对应 attempt；输出只写当前轮次 | 同轮和跨轮引用均可溯源；不覆盖或改写 CPU 来源产物 |
| 跨轮复用 CPU 成功凭据 | 必须满足新契约，且有当前轮次明确授权和独立预算 | CPU 成功只证明既定契约已验收，不自动授权新的等待窗口或 CUDA 执行 |
| 等待中无空闲 GPU | 只在本轮预算内前台观察，启动前重新核验空闲同类设备并按 UUID 绑定 | 查询失败或存在他人 compute 进程时不启动；记录实际采样时间与间隔 |
| CUDA 验收成功 | 保留 CPU 来源信息、当前快照、设备、内外退出码、完成状态及产物哈希 | 全部验收条件通过才报告 CUDA 成功；本地 CPU 测试不能替代 |

环境字段、规范化和比较范围以共享 helper 的 schema 为单一来源，CPU/CUDA 不另写两份规则。快照需覆盖解释器与前缀、依赖清单、实际导入来源、执行相关的自定义加载及精度/运行设置；禁止导出凭据或环境变量全集。SHA、轮次、时间戳及已授权 GPU 分配属于来源/运行记录，不能被误判为依赖环境变化。CPU 验收前后核对源码集合与环境字段未改变，将两份快照哈希绑定至验收报告。契约快照与普通环境探测报告使用不同产物，避免覆盖。这里验证的是明列字段的一致性，不声称整个 venv 的二进制逐字节相同。

修改范围限于验收 helper、CPU/CUDA 入口、driver、对应回归测试及本轮说明与交接。模型、训练逻辑、数据规则、配置、既有科研测试语义和版本 pin 不变；旧轮次文件不改写。

## 现场自主权与执行边界

沿用 [现场授权边界](server_autonomy.md)。ENV-005 总上限 45 分钟：CPU 验收与现场修复最多 15 分钟，GPU 等待最多 20 分钟，CUDA 执行最多 10 分钟。CPU/CUDA 各最多两次 attempt，第二次仅处理已定位并修复的临时故障；确定性代码、测试或契约失败不得碰运气重试。成功阶段不重复执行，新 attempt 使用独立输出。

各阶段使用不可重置的累计截止时间，失败、修复、补跑及 TERM/KILL 宽限均计入；额度不可挪用。等待检查间隔至少 60 秒，剩余预算不足时不为凑采样缩短间隔；到期后只做必要终止与证据归档。不共享他人占用的卡、不抢占、不部署后台轮询；CUDA 只用一张确认空闲的 GPU。

CPU 与 CUDA 均成功：`status: COMPLETED / readiness: ready_for_native_profile`。CPU 成功但等待结束无空闲卡：`status: COMPLETED / readiness: partial / cuda_smoke: deferred_no_free_gpu`。执行、测试或契约失败：`status: FAILED`；缺前提尚未执行：`status: BLOCKED`。所有结论以实际产物为准，新的真实数据实验仍需本地下一轮交接。

## 风险与待测

- 文件集合不完整会漏掉新增执行代码；环境比较过弱会复用失效凭据，过强则可能再次误拦纯回执变化。需分别覆盖两类边界，并检查 CPU/CUDA 确实调用同一 helper。
- 需回归同轮/跨轮来源解析、旧凭据拒绝、环境差异、文件增删改、输出隔离、预算不重置与信号退出；检查契约快照不会被后续环境报告覆盖。
- 本地检查已完成：95 项项目测试、15 项旧审计、21 项 setup 测试（17 项新契约 + 4 项状态/信号），新契约在 python -O 下 17 项通过；Shell 语法、8 段内嵌 Python 语法、交接命令语法与 git diff --check 通过。
- 使用真实本地解释器/NumPy/PyTorch，验证了重复环境采集稳定，并以临时回执夹具执行 CPU 入口的实际 acceptance 代码块，再由 CUDA 共用 helper 验证。夹具只检验接口衔接，已删除，不构成服务器 CPU/CUDA 成功证据。本地 uv venv 无 pip，夹具仅对子进程临时使用标准库自带 pip wheel，没有安装或修改现有环境。
- 已独立审阅 editable freeze 规范化边界。ENV-005 尚未执行，服务器 pin 与 GPU 仍须按新交接验证；可能再次因无空闲卡返回 partial，不预报 CUDA 耗时、显存或成功结果。
