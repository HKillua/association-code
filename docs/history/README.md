## 数据与方法教训

- 旧scene64有实际/名义时间错位：53锚点96.92%的已观测token错位超过1秒；同26,372个9001 token对实际时刻reference平均位置差0.523米，对名义时刻为280.963米。这是配准诊断，不是网络误差。当前使用真实native时刻及同一物理query监督，旧分数不与新协议混排。
- 全部576训练/开发场景已装配核验：T_core512/V64，54,792/1,635条有效轨；cap128保留78.62%/97.35%原生点。gap600监督覆盖76.7648%/76.1107%；缺口主要因query超出身份reference时间范围，不造真值、不删身份。完整数字与规则已合入[数据契约](../data_contract.md)，不重复扫描。
- 9001与reference有1,112,337个已审点四状态完全相同；官方速度单位说明冲突，8个固定场景几何差分更支持节。原生数据可研究关联与缺失恢复，但不能直接宣称两路独立噪声对无噪真值的融合降噪，也未发现输入/目标单边单位换算错误。
- 21分钟来自人为设定`(64−1)×20秒`，不是论文公开窗长。训练场景/片段跨度中位119.7/24.5分钟，当前Q64间隔中位114秒。21分钟滑窗虽保全部短轨，却使37.49%原同身份对不再共窗、轨窗口副本增至4.32倍，未采用。
- 训练侧全部片段×Q64中，自身区间内25.97%；自身外但同身份其他片段覆盖46.42%；身份包络内全部片段无支撑5.44%；身份包络外22.17%。这是oracle端点支撑上界，未按reference过滤，也不等于实际抽到或正确关联了辅助信息。当前正常评价按真实输入支撑分层，不为此另开诊断轮次。
- 数值修正、训练机会和机制改动同时存在时，不能把全部收益归创新。CPU测试只验证实现；接受负结果，先用当前普通融合/同容量门控对照判断贡献，不反复添加前置流程。
