# 015 模型、数值与机制复核

复核对象：`COOPERATIVE-COST-20261018-015` 已返回的原始 history、四臂评价、同一组 scores；执行代码为 015 当时的 `association/cooperative.py` / `cooperative_training.py`。本节不把成本测量当充分训练，也不对未取回的权重或物理预测数组作反推。复算入口：`model_diagnostics.py`，输出 `model_diagnostics.json`。脚本只读已有小产物，另调用初始化模型的头部做纯 CPU 合成尺度诊断；无训练、无原生 ZIP、无新真实模型推理、无 GPU、无 T_test。

## 1. 已证实的实际异常：身份门控几乎二值化

29,008 条 s0 logit 的范围为 −12,349.51 至 11,974.20，中位数 −1,258.33。使用返回数组按实际代码作 CPU FP32 复算：21,551 条 `sigmoid(logit)` 恰为 0，6,215 条恰为 1。两端精确饱和合计 95.72%。

门控为 `w = 0.001 + 0.999 * sigmoid(s0)`。分组却使用在全 V 上选出的阈值 −11,878.2002，接受 29,002/29,008 条边。因此“被接受进入同一组”与“融合时被赋予有意义的辅助先验权重”在这次未校准模型上明显脱节。这两处不同操作符合当前代码设计，不是布尔比较写反；它揭示的是分数尺度和概率门控目前不能按理想语义解释。

| 使用范围 | 实际 anchor-helper 数 | 权重恰为下限 0.001 | 权重恰为 1 |
| --- | ---: | ---: | ---: |
| 预测分组 | 1,571 | 1,223（77.85%） | 310（19.73%） |
| 真实身份分组 | 1,258 | 883（70.19%） | 339（26.95%） |

真实身份分组里也有七成真辅助轨被压至下限，说明不能仅把该现象归因于预测错配。这里的权重是加入注意力 logit 的先验质量；**不等于最终实际 attention 权重为 0.001**。模型依然可能依靠注意力内容 logit 改变贡献。

`utility` 路由进一步乘 `clamp(mean(predicted_utility), 0, 1)`，因此它不能恢复被 s0 压低的权重；对已经在下限的 helper，utility 也只能维持下限。这轮没有返回逐查询 utility 输出，不能量化剩余辅助轨究竟被 utility 如何抑制。

## 2. 找到可复现的数值路径：未缩放时间支撑特征及平方量级乘积

`cooperative.py` 的 s0 头将 `first / last / span / log1p(count)` 直接拼接，再形成两轨支撑特征的乘积 `sl * sr`。这些时刻是固定 20 秒单位的相对时间，不是归一化到单位范围的输入。数百个 tau 的轨迹会产生数万至数十万的支撑乘积，而 Transformer 编码经过 LayerNorm，典型量级完全不同。`_query_support` 中的查询到首尾的距离也未经缩放，进入 utility 和普通 learned gate。

纯 CPU、seed20、与015相同模型规模、语义 pooled 与 query summary 全部置零，仅改变合成时间跨度，得到：

| 场景跨度 tau（秒） | 最大时间支撑乘积 | 未训练 s0 logit | 未训练 utility 值域 |
| --- | ---: | ---: | --- |
| 1（20秒） | 1.21 | 0.206 | −0.085 至 0.116 |
| 10（200秒） | 85 | 8.00 | −1.30 至 1.22 |
| 100（2,000秒） | 8,500 | 744.77 | −13.41 至 11.72 |
| 350（7,000秒） | 104,125 | 9,089.74 | −47.20 至 40.98 |
| 1,000（20,000秒） | 850,000 | 74,132.84 | −134.99 至 116.87 |

这证明**即使完全没有语义内容，当前头部也能只因时间尺度产生本轮同量级乃至更大的极端分数**。但本地没有015训练后权重及真实逐轨原生支撑数组，不能把这张合成表冒充实际权重的因果分解，不能声称已证明时间特征解释了全部分数。

处理建议：正式继续训练前明确处理这些手工时间特征的数值条件，同时保留原始物理时间供连续时间编码、支持区判定和物理评价使用。可用固定、训练侧定义的单位缩放或显式有界变换，保留旧 checkpoint 的旧解释并在新配置中标明。**不能为了改善结果临时重选 V 阈值，或直接拿选择阈值充当融合门控的校准常数。** 时间特征变换会改变模型输入表示，须由主线程根据最新用户授权决定是否作为明确数值修复实施；本复核未改模型表示；后文所述被动日志修复不改变训练语义。

## 3. teacher / utility 的监督线路正确，但实际信号质量尚未成立

代码核对结果：

- teacher 对每条轨的单轨输出用该轨自己的 reference；正对才额外监督双轨融合。BCE 身份监督同时训练 s0。
- utility 使用单独深拷贝、eval、冻结的 teacher；两方向分别以各自 reference 比较单轨与加辅助轨的误差。负对辅助轨没有被偷偷当成同一目标。
- `physical_errors` 使用训练原生 std，考虑经度/航向最短角差；utility 残差为 `(e_self-e_cross) - max(e_self, epsilon) * u`。teacher 误差已经 detach；V 没参与效用标签训练。
- utility 阶段只更新 query_pool 与 utility_head；adapt 只更新 decoder / state_projection / role_embedding，learned 臂另外更新 ordinary_gate。s0 和 encoder 在四臂 adapt 中冻结，四臂共用同一组原始关联分数。

因此未发现“reference 泄漏进入推理”或“效用标签梯度偷改 teacher”一类确定实现缺陷。然而 teacher 仅 2 次更新；其内部单轨/双轨误差、效用正负比例、强度、可预测性都没有记录。**冻结 teacher 产生了标签，不等于这些标签已是可靠的辅助效用信号。** 两次 utility loss 从 28.25 到 27.53，样本场景不同，不能当验证误差下降，也不能认定效用已学会。

最小补强不是再造训练框架，而是在已有 `train_batch` 已算出的张量上记录：BCE 与四属性物理损失、utility 自身/跨轨误差及收益正负比例、utility 预测与路由截断比例。保留采样、损失、梯度和更新完全不变。实际权重与已保存的物理预测取回后再做只读诊断，无须为取证重新训练。

## 4. 两步后的四臂位置排序不能证明效用机制

plain / identity / utility / learned 从同一 teacher 状态出发，adapt 的采样种子相同、endpoint mask相同、每臂 2 步各使用32正对，valid_counts 与 removed_observations 在同一步完全相同。代码确实保留了这些控制。

但门控在首次 adapt 之前就不同：plain 每轨先验权重为1；identity 大量抑制至0.001；utility 进一步抑制；learned 使用一个独立初始化、只训练两步的普通门控。**即使 utility 未学得正确效用，仅改变注意力的辅助输入强度也可以产生位置排序。** 目前 oracle 位置 MAE 顺序 utility < identity < plain/learned，说明值得检查门控行为；不能据此称机制验证成功。速度并未一致改善，所有完整物理指标距离可用仍很远。

尤其不能将015比014的巨大位置误差改善归因于效用创新：015从一开始就带训练统计量的坐标输出映射，014执行的是旧 raw 输出参考；模型、训练、singleton 策略也不同。两者不是受控机制对照。

## 5. 速度异常还不能定性为 softplus 饱和

当前候选速度输出为 `softplus(z * 415.2732 + 109.0052)`。大 std 会放大未收敛的归一化输出扰动。负侧 raw 可使 softplus 及梯度接近零；大正侧则近似线性，能直接产生很大速度。

返回的只是速度 MAE（约752—1,084原生单位），没有各预测值、各目标值、raw speed 分布或梯度。**MAE大不能区分大量近零预测与大量过大正预测，更不能声称已经观察到饱和。** 先取回015已保存物理 NPZ，检查预测/真值速度分布；raw projection 与梯度需已有权重上的诊断或后续新增日志。此时不应擅自改速度单位、裁剪真值、改精度或换 loss 来做出好看结果。

## 6. 有限训练与回执纠正

| 阶段 | 真实训练范围 | 观察 |
| --- | --- | --- |
| teacher | 2步，128抽样对，4个场景，合计110个不同场景内对 | loss1065.09→412.52；clip前范数11574→9596。没记录 BCE/物理损失分项，不能证明何项主导 |
| utility | 2步，128对，4个场景 | loss28.25→27.53；clip前范数178→181 |
| 每臂 adapt | 2步，64正对，2个场景 | loss约13→12；clip前范数30—43，四臂均有限 |

上述范数都大于 clip1，实际应用了裁剪；仅凭总范数不能断言某模块的梯度完全被压制。不同 batch 的 loss变化不构成收敛曲线。这是已批准的成本测量，不能把“每阶段2步”叙述成完整预实验训练。

服务器 S2L 称 history 每步 `unique_pair_count=64 / duplicate_pair_count=0`，这点错误。teacher第2步的正例场景4838只有14个不同对，32次抽样中重复18次；全批 unique46 / duplicate18。符合既定不足32对时允许带放回的采样规则，不是需要删掉的坏样本，但回执摘要应据原始 history纠正。

## 结论边界

已证实：训练执行完成、关联门控大量饱和、阈值几乎全接受、真实身份辅助轨也大量被压到权重下限；代码存在能单凭时间尺度产生极端分数的路径。尚未证实：时间特征是所有异常的唯一原因、teacher效用可靠、速度饱和、四臂排序可重复、新方法超过充分训练的baseline。本轮优先解决数值条件与取证缺口，保留并行baseline路线，不因候选跑通而停止参考复现。

## 本轮已完成的普通日志修复（不改变研究语义）

在原有 `train_batch` 返回的 `loss` 之外新增 `loss_components = {physical, identity_bce, utility}`：physical 保留原本的方差权重与 regularizer；不适用分项为0。每个流式 pair 仍在同一位置反向传播，随后把已存在的标量 loss CPU 传输替换成4个 detached 标量的一次传输，没有新增推理、随机抽样、反向或同步次数。分项之和与原 loss 允许浮点加法舍入误差，不反过来用分项重构优化目标。旧015 history 未被补造分项。

验证：`python -m unittest tests.test_cooperative_training`，11项通过（0.858秒）；原有整批与流式 teacher 比较同时核对物理与BCE分项，utility以及fit各adapt臂核分项总和。另将修改前捕获的源码与当前函数在同样合成输入、seed、Adam、dropout0.3条件下，对teacher/utility/identity/四种adapt路由各跑2次更新：**原loss、原报告字段、模型及loss参数、梯度、优化器状态、RNG状态逐项完全相等**。记录见 `model_loss_logging_verification.json`。这些是CPU软件等价验证，不是新真实MTAD训练。

## 最小后续取证与方案边界

1. 优先由016在服务器读取已有256份NPZ做完整逐点复算、速度分布，并回传固定规则选出的少量场景四臂原件。本地只对收到的案例独立核坐标；全量报告明确为服务器CPU复算。若之后需要全量本地复算，可再通过既有传输方式取回39.3MB原件，无须重新推理。只分析既有V，不重新匹配或重选阈值。
2. 若要定位s0分量，取回已有teacher与utility checkpoint（先无需全部adapt权重）。已有分数与权重能检查head/LayerNorm参数和异常尺度；对**实际**时间特征贡献、teacher效用标签，还需要完全一致的既有训练原生输入/打包缓存或明示的CPU重建。仅权重不能还原已丢失的训练batch中间量，不建议伪造“精确重放”报告。
3. 数值方案优先候选为：用固定T_core统计量缩放手工时间特征，然后才组成差与乘积；连续时间Transformer输入仍是既定20秒tau，支持区判断仍用原始tau，不增加特征、不裁剪、不动标签/采样/损失。缩放参数只用训练侧、记录并随checkpoint保存；具体定义应先固定，不能为V分数选缩放系数。备选是原样增加训练，但当前饱和和近随机排序使“仅等更多步自然解决”风险更大。二者仍需要真实训练验证，不能凭CPU诊断提前宣告修复有效。
