## 2. 效用位置改善存在，但有明显代价

以下位置MAE单位为公里；四臂评价人口、分组和报告的支持计数一致。已知真实身份的oracle诊断把关联错误隔离开，不能充当实际部署结果。

| 四臂 | 预测分组位置MAE | oracle位置MAE | oracle缺失区位置MAE | oracle速度MAE（原生数值单位） |
| --- | ---: | ---: | ---: | ---: |
| 普通融合 plain | 209.19 | 198.86 | 196.15 | 883.86 |
| 身份门控 identity | 189.63 | 182.23 | 159.73 | 1079.87 |
| 身份×效用 utility | **179.62** | **170.39** | **150.78** | 1034.88 |
| 同容量普通门控 learned | 212.60 | 198.88 | 195.36 | 910.29 |

oracle完整覆盖377个目标、18364个有效位置点，包含全部1302个缺失区点。在这个全人口诊断中，utility相对plain位置MAE下降14.31%，61/64场景、16/17共享身份组件改善；相对identity下降6.50%，52/64场景、15/17组件改善。这不是只靠单个异常场景撑起来的均值。

但以下反证必须同时保留：

- utility的oracle速度MAE比plain**增加17.09%**，57/64场景恶化；预测分组下增加39.06%。航向没有稳健改善方向。不能只拿位置一列宣称完整四属性任务更好。
- 预测分组的缺失区相对identity，位置加权均值仅改善1.92%，42个有交集场景中12个改善、30个恶化；最大的5个改善场景贡献90.5%的正向变化，不能概括为缺失区普遍受益。
- oracle中的19个单轨目标没有辅助轨迹可融合，utility仍有137.34公里位置MAE，比plain的130.64公里更差；其中已有观测支持区也达136.09公里。当前共享解码会严重损坏本来较准确的已有观测，完整覆盖并不等于恢复有效。
- 简单融合的oracle已有支持区位置MAE约1.80公里，utility同类区域约171.89公里；单源9001约0.348米，但支持覆盖不同，且数据存在9001/reference数值复用。不能用这些均值直接混排，更不能说候选已胜过简单方法。

17个共享身份组件的成对bootstrap只描述本次固定快照的场景差异：例如oracle utility−identity位置MAE区间约−14.58至−10.33公里。它不包含训练种子或收敛不确定性，54项探索性比较也没有多重校正；不能代替完整训练与独立测试。

## 3. 代码中已定位的数值风险，而不是已证实的唯一根因

身份头直接使用片段起止/跨度及两轨支持向量的乘积。Transformer的时间编码按已批准的20秒单位输入，但这些额外MLP特征没有进一步缩放；数百量级的tau乘积可到数万甚至更大。CPU固定初始化反例中，仅把时长从tau=1改到350、语义特征保持0，身份logit从约0.206变为9089.7。这个路径足以制造极端logit，不过它不等于对015训练后全部权重做了因果分解。

真实缓存同样有异常：93.60%的logit落在≤−88或≥88。预测分组实际使用的1571个anchor-helper中，1223个身份权重在FP32中恰为最低值0.001；oracle1258个真同身份helper中，883个（70.19%）也是如此。分组按极低阈值几乎全部接受，融合却按未经校准的sigmoid把大量helper压到底，二者行为明显脱节。

这不是现在改一个验证阈值就能解决的，也不能凭分数极端就偷偷改变训练分布、门控含义或特征表示。当前实现符合先前记录的raw时间特征规格，未发现标签、推理顺序或数组长度的确定程序错误。推荐的最小研究修订是**仅对MLP手工时间特征采用固定训练侧尺度**，保留原时间编码与物理支持判定、无裁剪、无新特征；具体统计规则需要单独审阅，当前尚未启用。

teacher总loss从1065.09降到412.52，但它混合BCE和物理目标，旧history未保存各分项，不能把这个数直接叫作关联BCE。梯度裁剪前范数约11574和9596，反映优化信号很大，却不足以确定哪项占主导。可以直接补齐被动分项日志，保持原loss计算、反向次序、RNG和参数更新不变；不重跑015补日志。速度std约415引起的输出尺度风险，也须用真实数组区分大正预测与softplus低端饱和，暂不按假设改模型。

## 4. 这次和baseline是什么关系

014评价的是013各阶段只更新两次的TMTAFF近似参考；015是独立共享编码/解码候选。候选约170公里与旧参考约12901公里的oracle误差差距，混有输出坐标起点、架构、损失、优化量等差异，**不能归因于效用门控**。

014定位的参考位置输出尺度问题已经实现修正并通过CPU验证，但修正后尚无真实训练结果。下一份有意义的完整系统表应来自这个修正后的参考与训练更充分的候选，使用同一完整评价人口，同时披露更新量、正对数、优化器、选模、单轨输出策略和计算成本差异。候选内部四臂才是本轮机制归因比较。
