# 21分钟是否合适：训练侧时间任务分析

2026-10-19。分析完成；未改模型、输入时间轴、采样、标签、指标或执行预算。仅复用已有端点元数据，没有重扫原ZIP、读取reference/T_test或运行GPU。

**当前建议：不把21分钟切窗作为下一轮的默认设定或前置条件。先保留当前任务，检验已完成的候选v2能否恢复基本观测质量，并利用正常预测产物分开解释自身支撑、辅助支撑和无支撑外推。** 这修正了此前“先切21分钟窗再比较”的建议，不表示原全场景任务已被证明最合理。窗口方案仍未批准；新增训练预算仍为0，017按原任务继续。

## 1. 21分钟从哪里来

如果人为规定64个查询点相邻20秒，则首末跨度为`(64−1)×20=1260秒=21分钟`。**这里“实际查询间隔20秒”是新提议，不是原编码参数必然要求。** 既有`time_unit_seconds=20`只缩放时间编码；TMTAFF给出共同时间范围和长度64，未公开可还原的窗口秒数/步长。[文献和源码核验](../external_mtad_processing20261019/README.md)已完成，本轮没有重复检索。

当前512个训练场景、54,792条有效片段的时间尺度为：

| 量 | 中位数 | 说明 |
| --- | ---: | --- |
| 场景首末跨度 | 119.7分钟 | 当前全场景任务通常接近2小时 |
| 单片段首末跨度 | 24.5分钟 | 不能等同于整场景时长 |
| 当前Q64相邻查询间隔 | 114.0秒 | 不是20秒；随场景跨度变化 |
| 源9001原生相邻点间隔 | 30秒 | 来自此前完整训练审计 |
| 源9002原生相邻点间隔 | 15.72秒 | 不等间隔，与9001不同 |

同身份所有片段首末区间合并后，有10,280段内部空档，中位363秒、P95约1104秒。虽然98.17%的空档长度不超过1260秒，**窗口还要容纳两侧上下文，且固定边界会切断片段对，因此不能据此证明21分钟覆盖充分。** 空档也不保证有reference真值。

## 2. 切窗改变的不只是补全距离

只按已有首末区间模拟候选窗口，不训练、不按V得分选择窗长。起点对齐20秒，闭区间相交即纳入；所有原有效片段都至少进入一窗。分母为训练侧原110,733对同身份片段。

| 窗长 / 步长 | 非空窗口数 | 原同身份片段对至少共窗 | 不再共窗的原正对 | 轨迹窗口副本 / 原轨 |
| --- | ---: | ---: | ---: | ---: |
| 5分钟 / 2.5分钟 | 23,772 | 34.88% | 65.12% | 14.08倍 |
| 10分钟 / 5分钟 | 11,662 | 44.70% | 55.30% | 7.59倍 |
| 21分钟 / 10分40秒 | 5,555 | 62.51% | 37.49% | 4.32倍 |

21分钟方案仍保留全部31,862对原本时间重叠的跨源正对；但原不重叠正对中，同源只保留51.21%，跨源只保留39.91%。它主要缩小了接续关联的范围。先逐场景算覆盖再平均，三套共窗率分别为35.84%、46.02%、64.15%；结论不依赖只报大场景占权的总数。

因此，“全部短轨都保留”不等于“它们的关联任务都保留”。不共窗的正对没有变负，也不应被当作不合理样本；局部窗可以是合理研究任务，但其分数不能直接替代原全场景分数。轨迹副本数也不是GPU时间倍率：单批计算和遍历窗口终评的成本不同。

## 3. 自身没有观测，不等于所有传感器都没有信息

按当前场景Q64统计54,792条片段，共3,506,688个`片段×查询时刻`：

| 时刻类别 | 占全部 |
| --- | ---: |
| 在该片段自身首末区间内 | 25.97% |
| 在自身区间外，但同身份其他片段覆盖 | 46.42% |
| 在身份观测包络内，但所有片段均未覆盖 | 5.44% |
| 在该身份全部观测包络外 | 22.17% |

在自身区间外的人口中，62.71%仍处于同身份其他片段的首末区间。这说明大量单轨缺测存在**潜在辅助信息**，与我们做补全—关联—融合的目标相关。

这里合并了真实同身份的全部片段，是**oracle潜在支撑上界**；不等于训练时抽到的单轨/两轨已经具备这些信息，更不等于预测关联组能正确获得它们。端点区间覆盖不保证有同时刻原生点、属性完整或可评真值。本统计未按reference过滤，22.17%的包络外时刻也不能全部称为模型必须恢复的缺失真值。此前3个V场景的合法监督比例使用另一个分母，不能混算。

## 4. 对当前低分的判断

存在时间任务风险：017的TCM从原生相邻点学习，推理可能递归预测很远；候选teacher单轨恢复整场景中的合法目标状态，也可能承担较长无辅助预测。当前证据还不能量化这部分对最终误差的贡献。

但长时预测不足以解释全部失败。[018结果](../cooperative018_local_review/README.md)中，同一oracle分组、已有支撑的17,062个共同位置点，候选仍约55–56公里误差，简单融合约1.797公里。**先把有输入支撑的恢复做好，是比先改变评价任务更直接的检验。** 这也是已实现v2使用可见位置底座＋残差、修正速度/航向表示的动机；尚无真实GPU结果证明这些改动成功。

## 5. 下一步保持简单

1. **017继续当前配置，等待终态。** 本轮没有发现必须终止它的新数据解析错误。
2. **候选v2保留已完成实现，不再强加切窗重构。** 下一次训练仍须先确定正式训练配置和新增预算；本分析不是开跑授权。原任务未变，更容易判断基本恢复是否改善，但v2多项改动一起出现仍不能逐项归因。
3. **分层分析随正常评价完成。** 保留全人口主结果，再区分自身支撑、实际所用辅助片段支撑、双方无支撑及离最近可见输入的距离。预测分组按实际组成员统计，oracle分组单独报告，不能用真实身份修补预测输入。现有预测导出包含时间、输入mask、组成员和物理结果，无须先增加GPU诊断轮次；这些新分层尚未声称已在全量预测上算完。
4. 若有支撑区已恢复而长时无支撑区仍主导失败，再讨论局部任务的最大预测跨度、跨窗关联如何计分。需要改窗时，baseline和候选采用同一新协议；不能只裁候选难例，也不能用局部成绩宣称全场景成功。

这是当前证据下的推荐，不是“整场景永远更好”的结论，也不是对TMTAFF作者窗口的复原。此前[21分钟草案](../../proposals/local_time_windows/README.md)保留为未采用备选，不继续作为当前实验的阻塞项。
