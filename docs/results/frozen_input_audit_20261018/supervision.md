# 监督缺口原因审计：冻结 T_core512 / V_select64

2026-10-18。此处补足此前约 23% 查询无监督的原因，不修改生产 mask、划分、标签、查询网格或训练分布。仍是离线 CPU 数据结果，不是模型效果。

**结论（按四维全部有效查询口径）：gap600 下，T_core 缺口的 99.4657%、V_select 缺口的 99.8439% 来自查询时刻位于该身份实际参考时间支撑范围之外。其余来自参考属性无效或同一时刻冲突。不是整份参考文件缺失，也不是这次查到的时钟偏移失败。** 支撑范围只按实际数值参考时间的最小/最大值定义，没有将理论身份存活区间、标签片段时长或传感器观测时长冒充参考支撑。

## 实际规则与复核

读取 `association/fusion_targets.py:align_reference_states` 的实际规则，逐 query、逐 feature 分类：

1. 无该身份参考行、身份格式无效、没有数值参考时刻分别记账。
2. 精确时刻按该时刻所有重复行处理：任一行属性无效优先记无效；全合法但数值不同记同 time 冲突；否则有效。
3. 非精确时刻先判参考时间范围外，再判相邻参考 gap 超界；未超界才判断端点属性无效/冲突，最后判断航向恰好 180° 的圆弧歧义。
4. 对两个端点分别含无效与冲突的情况单列组合类，避免重复计数。单一合法 course=360 复制为 0；同刻 0/360 仍按原始值冲突处理。

分类器先通过 10 个合成案例，覆盖全部 14 类。随后每个真实身份在 gap180 与 gap600 下，分类为有效的布尔 mask 均与生产函数**逐位相等**；每个 scene 的 gap600 有效计数均等于前次时钟审计原件；每个 feature 所有分类之和均等于原查询分母。异常即停，本次无异常。未修改或重新执行前次时钟证明脚本。

## gap180 与 gap600：覆盖和训练可行性代价

| 范围 | gap180 有效 lat/lon/vel | gap600 有效 lat/lon/vel | 收紧后减少有效查询 | gap180 四维全零监督身份 | gap600 任一维全零监督身份 |
|---|---:|---:|---:|---:|---:|
| T_core | 470,395（57.8780%） | 623,895（76.7648%） | 153,500 | 57 | 0 |
| V_select | 12,516（51.8733%） | 18,364（76.1107%） | 5,848 | 0 | 0 |

T_core course 两种 gap 都比前三维多 2 个有效查询，发生在 3190 和 1494；其余结论相同。gap180 的 gap 超界类别有 T_core 153,615、V_select 5,850 个查询，不能直接等同净覆盖损失，因为按生产优先级，部分原本端点无效的查询也先被归到 gap 超界类。

57 个 gap180 全零监督身份位于 34 个 T_core 场景。其每个 feature 的 3,648 个查询分为：早于参考支撑 1,068、晚于参考支撑 1,004、gap>180 为 1,576。例：scene 1622 / identity `671721000-1`，gap180 为 `[0,0,0,0]`，gap600 为 `[17,17,17,17]`。需要与有效原生 node 数联结，判断这些身份是否产生可抽取的正配对；此文件不凭标签行数冒充有效 node 数，也不擅自改变采样以回避它们。

首轮脚本保存了每 scene 全/任一 feature 有效 query 的交集/并集计数及全零身份数。追加请求到达时全量扫描已启动，没有在运行中改原脚本。后续仅补读上述 34 场景及 2 个 course-only 场景，共 36 场景，保存这些场景全部 **4,058** 个身份的 `valid_count[4]` 与零监督原因。未再次扫描其余 540 场景。

对全部 576 场景，两种 gap 的“全 feature 有效交集数”等于 lat/lon/vel 各自有效数，“任一 feature 有效并集数”等于 course 有效数。这严格证明前三维 mask 相同，course 是其超集；除 2 个已补读场景外四维 mask 一致。因此结合原全零身份计数及 36 场景补充结果，可以确认 gap600 下**所有标签身份每一维都有至少一个有效 query**，而 gap180 的任一维零监督身份恰好就是上述 57 个四维全零身份。结论不依赖额外读取其他场景。

## 建议提交确认的监督方案

- 有效域明确为上述真实参考支撑内、端点逐属性有效且没有同 time 冲突的位置；不外推到支撑范围外、不跨越无效点补真值。关联标签与完整身份人口仍保留；覆盖不足单独报告，不用删目标提高分数。
- 首轮完整流程的待审候选可采用 **gap600 的显式逐属性 mask**，同时按精确 / gap≤180 / 180<gap≤600 分层报告监督数量和误差。其理由是本范围下保留全部训练身份的四维监督，避免 gap180 新引入的 57 个全零身份；这不是因为其分数会更高，也不证明 10 分钟线性插值一定符合运动真值。
- gap180 是更少依赖长跨度插值的备选，但不能仅把配置从 600 改成 180 就宣称等价实验：当前 TFM 对无有效监督 batch 会失败，需先核这些身份的有效 node 和固定 seed 抽样影响，再明确无监督批次行为。不能通过删除身份或重抽到有监督为止来偷偷改变训练分布。
- 正式 gap 仍应由研究协议确认。本审计不批准训练或新 GPU 预算，不改变实现；两种 gap 的比较是诊断，不能按验证误差择优挑 gap，也不能把插值监督叫作原始精确真值。
