## 1. CL 校准修复了负样本无梯度，尚未证明距离学好了

从 `run.margin_calibration.samples` 的原距离与标签重算：64 批 × 64 对 = 4096 次呈现，正负各 2048；3927 个独立配对、169 次重复，涉及 116 个训练场景。采样发生在 **TCM 两步之后、TAM 更新之前**，TCM 为 eval，TAM 保留 train/dropout，且 `no_grad`。因此这不是固定 eval 表征的一次独立性能测试，也不能将 4096 个呈现当成独立统计样本。

对同一组距离，实际 CL 为 `0.5 * [y*d + (1-y)*relu(m-d)^2]`：

| 量 | 请求配置 m=1 | 校准 m=72.6415863 |
| --- | ---: | ---: |
| 负样本严格 hinge 激活 | 0/2048 | 1024/2048 |
| 负类平均损失 | 0 | 11.830893 |
| 正类平均损失 | 35.869188 | 35.869188 |
| 平衡批平均总损失 | 17.934594 | 23.850041 |
| 正例逐样本 `d loss / d distance` | +0.5 | +0.5 |
| 全部负例平均 `d loss / d distance` | 0 | −3.065329 |

校准后的负类平均绝对距离导数是正类的 **6.13 倍**；只看激活的负例，其均值为 −6.130658。这里是解析的**距离导数**，不是网络参数梯度，也不能说网络更新被负类支配 6.13 倍。64 对批均值再统一除以 64。原 `negative_hinge`、`loss` 和 `distance_derivative` 与复算一致。

| 距离分布 | 最小 | P25 | 中位 | P75 | 最大 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 真配对 | 59.5993 | 64.5381 | 68.8399 | 76.6099 | 115.1522 |
| 假配对 | 59.3772 | 66.4286 | 72.6416 | 82.5742 | 131.0631 |

两类范围与中间区间明显重叠；63.87% 正例落在校准 margin 内，37.06% 负例距离还小于正例中位数。**margin 变化本身没有改变任何距离或区分能力**，它只让当前表征尺度下的负类排斥项开始工作。高达 60–130 的距离也不能直接视为物理误差：TAM 是对 `64×128` 表征展平后求欧氏距离，原代码 `association/models.py:276–288`。

后续还缺各阶段固定 eval 模式下的正/负距离、hinge 激活与完整 P/R/F1。JOINT 会继续改变表征尺度，但当前记录没有 JOINT 后的距离分布，不能断言一次 margin 已失效，也不能自行再校准。TAM2 与 JOINT2 的 V_select macro-F1 分别为 **0.370771 / 0.362835**，阈值 **−62.4421 / −98.6680**；它们只是两个选阈值后的开发点，不是统计显著差异或长期学习趋势。`selection.candidate_count` 是阈值候选数，不能当作验证配对数。

## 2. 损失确实回传，但数值不等于物理效果

| 阶段 | 第1/2步 loss | 第1/2步裁剪前梯度范数 | clip=1 对应缩放系数 |
| --- | --- | --- | --- |
| TCM | 1.02812 / 0.97082 | 0.3903 / 0.3393 | 1 / 1 |
| TAM | 23.27068 / 35.39971 | 209.8203 / 335.8480 | 0.004766 / 0.002978 |
| TFM | 84.61626 / 79.33288 | 76648.3438 / 74.1594 | 0.00001305 / 0.013484 |
| JOINT | 120.95902 / 106.14118 | 493.9959 / 339.2654 | 0.002024 / 0.002948 |

字段：`history[*].loss/gradient_norm`；裁剪前语义由实际执行版本的 `association/reference.py:_update` 和 `association/fusion_training.py:163–170` 核实。缩放按 `min(1, clip/(norm+1e-6))` 复算。TFM 首步有非常大的有限总梯度并被强裁剪，值得后续观察；记录没有逐模块梯度，**不能归因为某个损失项、宣称发生持续梯度爆炸，或用该系数等同 Adam 参数步长。** 修改 clip、LR、损失权重、坐标归一化或输出初始化都属于训练配置/方法选择，不能包装成普通性能优化。

TCM 的约 1.0 是原生观测下一时刻的**双向 detached embedding MSE**，分母为各轨 `2*(点数−1)*128`；query/reference 不参与这个目标（`association/timed_models.py:121–141`）。两步 loss 下降不意味着物理轨迹补全误差下降，更不证明真实长缺口可恢复。

融合四个分项为：

| 阶段/步 | lat | lon | vel | cou | 融合总项 |
| --- | ---: | ---: | ---: | ---: | ---: |
| TFM1 | 20.03958 | 131.22296 | 11.38629 | 1.03851 | 84.61626 |
| TFM2 | 20.21714 | 128.68200 | 3.31685 | 1.20214 | 79.33288 |
| JOINT1 | 15.40574 | 126.41748 | 2.18880 | 0.99951 | 75.03046 |
| JOINT2 | 13.60897 | 125.06630 | 1.84980 | 1.00581 | 73.28254 |

字段：`fusion_component_losses` 与 `fusion_loss`。lat/lon 是原生角度上的 SmoothL1（beta=0.001），vel 是带 `1e-6` 的对数速度均方误差，cou 是 `1−cos(角度差)`，再加可学习方差的加权/正则（`association/fusion.py:161–224`）。它们不是同单位 RMSE，不能直接横比四列。接近 20/131 的初始位置损失**与未训练物理头离原生坐标很远相容**，但没有原预测，不能把“预测在零附近”认作已证实原因。首步近原生坐标量级提示不能把 80 降到 73 解读为融合已可用。

JOINT 的确满足 `association + 0.1*completion + fusion`：

| 步 | association | 加权 completion | fusion | completion占总标量 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 45.83496 | 0.093605 | 75.03046 | 0.07739% |
| 2 | 32.76346 | 0.095179 | 73.28254 | 0.08967% |

这里只证明标量尺度差别很大，不证明 completion 的参数梯度可忽略。四步物理训练使用不同场景/配对，TFM1→TFM2 的监督支撑比例也明显变化，因此这些值**不能当作同一评估集上的训练曲线**。

## 3. 有效监督：这四批能训练，不代表全量缺失区已经学过

`fusion_valid_counts` 是每属性在**呈现的正对 × 64 query**上的有效计数，重复配对会重复计数：

| 阶段/步 | 每属性有效/全部 query | 比例 |
| --- | ---: | ---: |
| TFM1 | 3988/4096 | 97.3633% |
| TFM2 | 2407/4096 | 58.7646% |
| JOINT1 | 1262/2048 | 61.6211% |
| JOINT2 | 1605/2048 | 78.3691% |

四属性在这四批内计数相同且均大于零。代码按有效批的各属性计数归一化；空 microbatch 不等于空有效批（`fusion_training.py:93–101,147–156`）。这能排除本次记录里“整批没有监督仍假训练”的解释，**不能将这些比例当成独立目标、整个训练集或真实缺失区的覆盖率**。`completion_target_elements` 在 TFM 阶段虽被记录，completion_loss=0，该阶段并没有执行 TCM 自监督更新。

当前 JSON 没有把这四批的物理损失拆成观测区、单侧缺失、双侧缺失、参考原始精确点/插值点；也没有最终 predicted-group / oracle-group / 单源 / 简单融合结果。即便最终全体误差好看，也仍需这些既定对照才能区分关联改善、参考与源9001数值复用、插值容易区域和真实缺失收益。013 本身没有提供“补全与融合优于简单方法”的证据。

## 4. 更新覆盖远低于“已看过数据集”

人口完全从原 `run.sampling.association` 复算：512 场景，54,792 个有效片段，18,249,384 全候选，110,733 正候选，18,138,651 负候选。片段数由各场景完整候选数 `n*(n−1)/2` 精确反解求和，无新数据读取或重建划分。原候选正例比例约 0.607%，训练批正负平衡是既定采样，故平衡训练 loss 不是原始候选上的表现。

| 阶段 | 独立场景 | 独立轨段/占54,792 | 配对呈现→独立对 | 独立正对/占110,733 |
| --- | ---: | ---: | ---: | ---: |
| TCM | 88 | 127 / 0.2318% | — | — |
| TAM | 4 | 99 / 0.1807% | 128→110 | 46 / 0.04154% |
| TFM | 2 | 67 / 0.1223% | 128→96 | 96 / 0.08670% |
| JOINT | 4 | 130 / 0.2373% | 128→128 | 64 / 0.05780% |

四阶段使用轨段的并集为 **422/54,792=0.7702%**，覆盖 96 场景。其中 TCM/JOINT 能更新前端表征的轨段并集仅 **256=0.4672%**；冻结阶段见过的片段不能加成 TCM 的训练覆盖。TAM+JOINT 关联更新仅 **238 个独立候选，占全候选0.001304%**；TFM+JOINT 物理融合更新仅 **160 个独立正对，占正候选0.14449%**。calibration 的 4096 次 no_grad 访问不能算训练更新。

这不表示必须遍历全部 1825 万配对才可学习；它只说明这次两步不够支持“模型已经充分训练但仍差”的结论。仅将各阶段改为 100/100/100/20，原采样下理论期望也只是：TCM 见到约11.03%轨段，TAM/TFM每类约17.76%场景，JOINT每类约3.83%场景，尚不能叫充分覆盖。随机访问一个场景也不等于学完该场景。

## 5. 已知成本与两种不同规模的计划

013 外层占用墙钟 3579 秒。训练步骤 750.620 秒（12.51 分钟，20.97%），一次校准1498.098秒（24.97分钟），两次验证1112.887秒（18.55分钟）。校准+验证合计72.95%。另有失败的终评79.385秒、run内未分项126.721秒、run外11.290秒。**这不是训练占GPU算力20.97%的利用率测量**，只是日志时间构成。

本次每阶段只观察到两个不同批次的耗时：TCM1.410–3.306秒、TAM11.638–24.390秒、TFM146.438–149.724秒、JOINT205.762–207.953秒。以下只做逐阶段 `步数×两点min/max`，再加一次校准1498.098秒、每次完整验证552.948–559.939秒。不是置信区间、预测区间、充分训练建议或预算保证；不包含未知最终完整评价、准备/IO/检查点与共享GPU竞争。所谓 GPU 小时在此是单卡作业占用墙钟的算术。

| 方案 | 仅训练 | 加一次校准 | 再加验证后的已知项 |
| --- | ---: | ---: | ---: |
| 100/100/100/20，每2步验证（60次） | 5.573–6.084 h | 5.989–6.500 h | 15.205–15.832 h |
| 同更新数，每20步验证（6次） | 同上 | 同上 | 6.911–7.433 h |
| 同更新数，每100步/阶段末验证（2次） | 同上 | 同上 | 6.297–6.811 h |
| 90%访问阶梯1971/1178/1178/1178，每100步/阶段末验证（24次） | 119.828–126.831 h | 120.244–127.247 h | 123.930–130.980 h |

90%阶梯来自[既有覆盖计划](../../tmtaff_complete_plan.md)；其90%指TCM轨段及pair阶段每类场景的预期访问，不是所有轨段/配对90%，更不是收敛。本算术说明，**沿当前实现无法用12/24小时承诺该覆盖量**。长阶梯外推尤其脆弱，两点耗时不能代表1178批的场景和轨长分布。

一次校准在原8步平均摊到187.26秒/步，在320步摊到4.682秒/步，长阶梯摊到0.272秒/步。不能从013“一小时只8步”直接线性推导320步要40小时；也不能把校准乘到每个epoch。相反，每2步全验证是会持续重复的成本。改变验证频率会改变选模机会，必须明示配置选择，不能称为结果等价的纯优化。

终评79.385秒只是被中断的已执行片段，**不是完整终评成本估计或上界**。要形成可承诺总预算，仍缺最终全目标评价的完整时间/输出，及已实施等价缓存后的真实步时。上表不能被直接转换成 READY 或服务器预算。

## 6. 什么可以作为实现优化，什么需要研究决策

| 事项 | 判断与边界 |
| --- | --- |
| 同一TFM冻结步只计算每个独立端点一次，后续复用完成表征 | 可作为等价效率优化：该阶段TCM eval/frozen，无梯度；需比较输出、损失、梯度/更新与RNG语义。原两批128次端点使用只有19/48个独立端点，存在重复；**不能按128/19、128/48直接折算总步时加速**，TFM及其他工作仍在。 |
| 复用完全相同已选状态的完整V结果/表征，避免终评重复同一推理 | 可作为等价效率优化，但必须使用实际selected状态，不能误拿最近JOINT状态；不能省略完整配对、物理目标或既定指标。 |
| 调大校准cache上限 | 原cache仅131,727,360字节、0次eviction，尚无容量瓶颈证据。不能把它当已证实加速措施。 |
| 把TFM的冻结缓存照搬JOINT | 不等价：JOINT需要梯度且有train/dropout；不同配对重复前向的随机性/计算图可能改变。 |
| 改margin样本数、更新量、验证频率、batch/microbatch、采样 | 必须明确新的训练/选模配置与公平对照；不能只标“修bug/提速”。其中microbatch改变时尤其要审dropout/RNG与归一化。 |
| 调clip、LR、坐标/输出初始化、loss权重、精度 | 影响优化或方法，现有两步不足以决定最佳方向。不可为降低loss或提高速度静默修改。 |

峰值 allocated **1.0224 GiB** / reserved **1.3672 GiB** 是本进程PyTorch分配器峰值。它既不是整卡显存使用，也不是SM利用率；launch快照0%利用率不能代表一小时内负载。可以提出后续测量并行/批处理效率，不能直接断言GPU闲置导致慢或可无代价提高batch。

## 7. 可供本轮决策的最小结论

先完成对当前执行路径的等价重复计算消除，随后把新的实测时间用于制定**一个完整流程开发预实验**：四阶段、完整终评、原生/缺失区分层、单源与简单融合、predicted/oracle分组都要出结果。100/100/100/20可以作为讨论量级，不能预先包装成论文已充分复现；90%阶梯是更大覆盖量的成本参照，也不是必须立即开跑的要求。

现有证据不支持“好idea已经失败”，也不支持“只要多训练肯定成功”。仍需可观察学习曲线和最终物理指标来区分训练不足、尺度/优化问题、原方法适配能力不足。保持现有训练人口和标签，不为了凑预算删难例或只评价有利区间。服务器新训练量与预算由本聊天明确后下发；本文没有启动、批准或承诺任何新GPU实验。
