# 数据、代码与论文协议复审

2026-10-18。用户要求重新检查整个实验设计。本次回读官方数据说明、原始Level2开发数据、TMTAFF/TSA/FESR/MVW/HTG全文关键方法与实验章节，以及当前数据、模型、采样、训练、选模和融合代码；重新计算010/011已有产物。没有启动新训练、修改执行代码或数据划分，没有读取T_test量测/参考。

**结论：现有实验设计确有需要先纠正的问题，不能再按现配置直接扩大训练。最严重的是输入和监督没有统一物理时间语义，其次是训练覆盖不足、对比条件混杂、完整任务评价未闭合。现有结果仍是真实的关联开发结果，但不足以否定补全—关联—融合路线，也不足以称为完整TMTAFF复现。**

此前我把多项适配差异列为限制，却没有在继续装配系统前把它们量化到足以判断是否可用。这是推进顺序上的问题。软件测试证明实现符合既定接口，不能证明接口所代表的研究问题合理。本次把两者分开审查。

证据标记：DE为数据/代码/产物直接证据，SC为论文或官方说明的陈述，AI为尚需归因的推断，UN为未披露或缺证据。完整独立报告和可复算CPU脚本在本地研究目录 `docs/reviews/2026-10-18_experiment_reaudit/`；论文原件也在研究目录，不要求服务器复制或重新调研。

## 1. 最高优先级：同一个槽并不代表同一个时刻

[当前注册](../association/data.py)对整个场景生成64个名义槽，再把每条片段按自己的首尾时刻插值，放到向外量化的槽中。实际时刻另存为`observation_times`；[TCM/TAM](../association/models.py)只读四维状态和槽位置，不读实际时刻。代码按声明契约执行，但这个契约不是严格的共同时间配准。

对**53个此前已审开发锚点**重新读取原始ZIP（DE）：

| 量 | 实测 |
| --- | ---: |
| 有效轨段 | 2887 |
| 名义槽间距中位数 | 113.71秒 |
| 实际时刻与名义时刻绝对差：中位 / P95 / 最大 | 25.89 / 85.76 / 114.14秒 |
| 偏移超过1秒的已观测token | 96.92% |
| 每轨已观测槽数中位数 | 14 / 64 |

例如`4999:9002:12`第27槽标为3083.14秒，却写入2969秒的状态。网络没有收到这114.14秒的偏移。

更直接的无模型对照：对9001输入，分别与实际时刻和名义时刻的reference比较。在两种查询都有效的**同一组26372个token**上：

| 同一份输入数值的比较方式 | 位置误差中位数 | 平均 | P95 |
| --- | ---: | ---: | ---: |
| 对实际时刻reference | 0.454米 | 0.523米 | 1.188米 |
| 对名义时刻reference | 150.197米 | 280.963米 | 962.679米 |

这是时间标注差异造成的对照，**不是网络预测误差，也不是已发生的融合实验失败**。诊断使用统一600秒参考插值gap上限和已审身份的显式时钟偏移；这些只是诊断约定，不是正式训练配置。两分支取共同有效交集，不能外推全部Level2。

[新融合监督](../association/fusion_targets.py)要求在名义grid查询reference，而TCM保留的是实际时刻输入的embedding。因此如果直接接起来，TFM既要处理运动时间错位，又要做融合；其收益无法清楚归因。TMTAFF原文要求共同时间范围注册，但没有公开足以支持我们这种全场景64槽近似的细节（SC/UN）。

**需要解决：统一输入、补全位置和监督的物理时刻。** 可选择严格共同时间窗口，或显式保留不规则时间的适配；前者更接近原文意图，后者改变模型时间表示。二者都要处理短片段，不能用删短轨掩盖问题。本轮没有擅选窗口、改采样或重建缓存。修正后必须重建受影响的输入与模型产物，旧checkpoint不能直接冒作新协议结果。

## 2. 训练确实完成了，但远未检验“完整训练后能不能工作”

直接统计[A_full完整history](../HandOver/results/COMPARE-20261017-011/afull/files/history.json)及[progress](../HandOver/results/COMPARE-20261017-011/afull/files/progress.json)（DE）：

| A_full实际训练暴露 | 数量 |
| --- | ---: |
| 可用训练场景 | 640 |
| 关联更新 | 100 TAM + 20 joint |
| 至少参与一次关联loss的场景 | **194 / 640（30.31%）** |
| 正例来源场景 / 负例来源场景 | 111 / 101 |
| 配对呈现 / 不同配对 | 7680 / 7070 |
| TCM不同训练轨迹 / 可用轨迹 | 6091 / 59870（10.17%） |

关联采样每次只从一个正例场景、一个负例场景取对；120步连场景都没覆盖一遍。TCM预训另接触577个场景，因此不能误说整套模型只见过194个场景。增加512→640训练池而维持120个关联更新，还改变归一化统计和抽样覆盖，不能单独识别“更多数据”的作用。

TMTAFF报告80epochs、长轨随机截断、各模块充分训练后joint（SC）；原文未给每阶段epoch分配和完整batch形成细节（UN）。不能把80epochs理解成全候选穷举80遍，也不能把100/100/20更新称为作者完整训练。下一方案应先定义epoch/样本单位、覆盖与学习曲线，再估预算，不能仅把100改为1000。

## 3. 目前的baseline比较混合了多个因素

010/011的A0和A_full是**TCM+CE关联适配**，未训练TFM。TSA是**离线表征/配对评分适配**，不是原文在线系统。CDF是A0上的候选头；它在现有协议下没有显示收益，这个负结果保留，不追加其训练。

| 对照项 | A0 / A_full | TSA离线适配 |
| --- | --- | --- |
| 关联正配对呈现 | 3840 | 512000，另有批内负例 |
| 时间信息 | 名义槽索引 | 使用实际时刻bin |
| 输入属性 | 经纬度、速度、航向 | 经纬度、时刻 |
| 增强/损失 | 无论文随机截断、CE | 任务裁剪、InfoNCE |
| 模型参数 | 2791168 | 474624 |

正例呈现量相差约133倍，训练任务、输入和成本也不同。现表可以回答“这几个实际产物在同一V候选上表现怎样”；不能回答“哪个结构在公平训练下更好”或“补全模块没有价值”。论文baseline按论文训练与机制消融控制训练条件，是两种不同比较，应分别标明。

TSA原文还有在线过滤、Hungarian、易难分级和时序确认。按本地已实现的原文时间适用规则，只有9710/29008候选（33.47%）、1791/3297正例（54.32%）在适用范围内。这不要求删除其他样本；应保留全量扩展任务表和共同适用子集表，不能把一次离线阈值与在线系统成绩混排。

## 4. 身份隔离有效，但当前V不能代表训练中的稠密场景

从既有512训练/64验证名单重新读**标签**（没有额外打开量测/参考），场景交集与A身份交集均为0（DE）。隔离是正确保护，应保留。

| 原始标签统计，清洗前 | T_core | V_select |
| --- | ---: | ---: |
| 每场景节点数中位数 | 37 | 20.5 |
| P95 / 最大节点数 | 384.3 / 2422 | 47.7 / 100 |
| 原始全候选正例比例 | 0.6140% | 11.3699% |

清洗后的对应比例为训练0.6068%、验证11.3658%；**实际训练batch仍是50%正例**，不能混淆自然候选比例和采样比例。当前V缺少训练中的大场景，其结果不能支撑千级片段场景能力。组件隔离及开发锚点归训练侧可能影响分布，完整因果仍需007原manifest确认。

这不是为了好成绩换划分的理由，也未证明Level2选错。下一步先用既有manifest报告组件和场景分布、界定结论范围；需要新增开发评价或改划分时再给具体方案，T_test继续封存。

## 5. 原生融合究竟能改善什么，必须先说清楚

重新比对53开发场景原始记录：9001的46127个唯一参考匹配点，**四维原始值全部等于reference**。另408行参考连接有歧义；结论不推广全部数据，也不是物理真值独立性的证明。9002的36310个唯一匹配点无四维完全相等记录（DE）。

因此，在已核验9001已有观测的位置，直接输出该源已达到参考零误差；不能期待平均加入另一源自然降噪。完整任务仍可检验缺失区间恢复、额外覆盖、正确关联和错误关联传播。应分开报告：9001/9002单源、简单融合、真实身份分组下学习融合、预测分组下完整系统；同时保留错误合并、拆分、漏目标及覆盖，不能只算成功关联点。

当前清洗也限定了任务：53场景删除116/3003节点（3.86%），失去465/6204无歧义正对（7.50%）；支撑内部插值成连续序列，模型只补两端。它目前不是同时处理端点中断、内部空洞、属性缺失的通用方法。需明确范围，不能把过滤后的全量称为原始所有目标。

官方使用说明明确速度为m/s，而TMTAFF报告使用kn。没有确定转换链前保留原生数值，并分别标注两份来源；速度极端值不构成猜测换算的依据。源号9001/9002不是Level1/2。

## 6. 代码复核发现的具体风险

| 项目 | 已证实内容 | 尚不能断言 / 处理方向 |
| --- | --- | --- |
| **TCM训练/推理注意力不一致** | 相同history、eval、dropout0，teacher与rollout第一步仍不同；多层模型只改encoder mask还不足，还涉及cross-memory mask | 不是未来信息泄漏；对011的实际影响未归因。需要统一并验证多层、矩形mask与多步语义，不能只修一行就称完成 |
| **新CL margin未经量级核验** | L64×128、6层、dropout.1的CPU初始化反例：相同输入train距离59.75、异输入67.82；margin1的负hinge均为0 | 原生CL未正式训练，不能用它解释011 CE低分。margin1是自定值，论文未给；需距离/激活率/梯度诊断后明确选择 |
| **CE无bias的局限** | 一维正距离1/负距离2可分例，无bias BCE最优仍约.642；但可通过阈值正确排序 | 论文Eq16本身无bias，不是确定漏写bug；不能从loss近ln2推导模型必然无用 |
| **TFM位置loss不连续** | 本地`paper_printed`把原文e记号解释为科学记数，切点.001；两侧损失/梯度约跳1000倍 | 原文`10×e⁻⁴`记号还有歧义；按自然常数解释也不连续，但不是1000倍。作者实现未知。不能继续把当前模式当可靠默认 |
| **全任务评价/选模未闭合** | 已有误差和覆盖原语，尚无完整目标对应/漏目标汇总；草案joint按关联F1选模 | 可能选中融合较差的权重；正式训练前必须明确三环节评价与选模，不能只补trainer就开跑 |

正面核验同样保留：未发现011参考状态/T_test进入模型、训练normalizer使用验证数据、普遍梯度断路、joint没加载前一阶段所选权重、阈值枚举丢候选等证据。融合微批损失分母、loss权重入optimizer等已有检查成立。没有找到能解释全部低分的单一确定bug。

## 7. 与论文的差异应该怎样解释

| 论文 | 本次确认的实验对象 | 对我们的约束 |
| --- | --- | --- |
| TMTAFF，PDF pp.6–18 | 3000场景7:1:2、64点、补全/关联/融合、随机截断、80epochs；Level与完整预处理未披露 | 作为完整主参考；不能把当前CE短训冒充它，也不能虚构作者未披露设置 |
| TSA-cTFER，pp.7–18 | 最长128原生点、双任务对比学习、150epochs、在线指派与确认 | 当前最多64有效点的离线适配应单独命名；完整在线复现是另一个交付范围 |
| FESR-LSTM，pp.2–5 | 共同时间区间差分窗口，均衡训练，最多50epochs | 它不能直接处理所有无交叠片段；高分依赖候选/窗口范围 |
| MVW-GNN，PDF pp.8–14 | 明确Level1训练/Level2外测；删单轨目标、只保留>100点轨迹 | 不能把它的筛选和数据用途推给所有MTAD论文，也不照搬test调参 |
| HTG-TA，pp.4–5、9–10 | AIS派生60秒场景窗、整场跨源矩阵、一对一约束 | 与同一身份多片段组合任务不同；不能直接套一对一规则 |

这是本次重点重审范围，不宣称已把全球所有论文重新逐篇审完。SCTA-Net缺全文不阻塞上述问题的判断；STAN已核为自建仿真数据，不能算MTAD实验证据。

TMTAFF/TSA的**mPCA是场景平均召回率，mPFA是场景平均1−precision**，不是macro-F1或FPR；TMTAFF的mwPCA还按预测关联对数加权。论文90%以上的数值不能直接与我们的F1对比。融合ME/ESD印刷也有疑点；应明确论文兼容列与可靠物理误差列的定义，不能为好看改已有指标。
