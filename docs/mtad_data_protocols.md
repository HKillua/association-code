## 2026-10-21：实际使用量与正式规模目标

用户明确要求正式实验的数据使用量与同行对齐。**当前512训练／64验证是开发规模，不作为最终充分训练或论文规模已对齐的证据。** 首要规模参照是TMTAFF：3000场景，2100训练／300验证／600测试；TSA-cTFER与MVW-GNN的4000／500／500作为另一规模参照。后者MVW为Level1且有轨迹筛选，不能仅按总数视为同任务；HTG-TA、TF-TS的10000／1000涉及AIS母轨与场景生成，也不是直接从本地5000场景包抽取。

当前043—049主线配置使用T_core512和V_select64，共576场景；T_test128仅选定封存，未用于模型测试。T_head128曾用于已退役CDF的heads训练，因此历史训练侧至少使用过640场景，但不能把它并入当前模型的512训练量。Level2原包共有5000场景；训练池54792片段、V1635片段不等于相应数量的独立场景，也不代表所有训练片段都被某一短训模型实际见过。当前训练场景数为TMTAFF的24.38%，达到2100需扩大约4.10倍。

**仅调大scene cap无法得到2100／300／600。** 原007先按shared-A传递组件分角色，再在角色内取cap：

| --- | ---: | ---: |
| T_core | 512 | 4014 |
| T_head | 128 | 399 |
| V_select | 64 | 426 |
| T_test | 128 | 161 |

保持既有组件角色时，测试上限161。即允许重分完全未暴露的整组件，依据已知暴露记录也至多剩312场可作新测试：强制训练组件与已用T_core、T_head触及组件的并集覆盖4327场，旧V64触及组件覆盖361场，剩余`5000−4327−361=312`。312是新测试集的总量上限，包含原测试角色池161场及已封存128场，不是还能额外新增312场。这是宽松上限，其他历史暴露可能继续缩小它；4327是组件隔离下必须留在训练侧的场景，不是已训练4327场。该核验只读取manifest与历史训练名单，没有读取测试量测/reference。

复核来源：Git `612afea:HandOver/results/EVIDENCE-20261018-012/prepared007/manifest.json`的`development_forced_components`、`splits`、`components`、`component_members`；同提交`HandOver/results/COMPARE-20261017-011/cdf/files/heads/selection.json`的`training_scene_ids`逐项等于T_head128。按组件求集合并集即可复算，无需扫描ZIP。

**用户随后明确选择“我们和TMTAFF保持一致”，正式采用场景级3000、7:1:2方向。** 新协议不受上述旧shared-A隔离上限限制；允许跨场共享身份并披露，不称身份独立泛化，不据此指控论文泄漏。保留旧测试角色，已直接用于训练/开发/预览的场景不进入新测试，因而属于带历史使用约束的固定随机划分，不是重建作者未公开名单。用户最新进一步明确正式使用Level1，取代先前Level2方向。旧Level2名单/时钟不复用，新Level1从头准备；两包共享A，旧Level2开发暴露须披露，不能把另一个包直接认作身份独立测试。具体规则见[正式数据约定](data_contract.md#当前选择与入口)。

本轮重核TMTAFF：p16 §3.1.1明确先抽3000 unique scenes，再随机7:1:2；p15 §2.5有长连续轨迹随机截短增强、SL64及80epochs；p6 §2.2.1有Z-score；p16–17按场景顺序拼接和原顺序取batch，逐场测试。其预处理引用[48]是Cui等数据集论文《基于全球AIS的多源航迹关联数据集》（2023，45:746–756，[DOI](https://doi.org/10.11999/JEIT221202)）。这些是已公开的处理，不是已证实的隐藏筛选；未写出本地Level、scene名单、split seed、SL64实际秒数窗或长轨裁取到64的完整规则。p15的seed20明确用于权重初始化，不能冒称作者划分种子；新名单采用20是本项目可复现选择。也不能把生成过程中的加噪/平移再次施加到现成包，或借其他论文删短轨、删难pair。

[48]本地全文PDF p4–6／刊页749–751已复核：原AIS母轨按>600秒间断切开、去静止/低速/跳变、保留>30点且>300秒，再作平移、共存时间调整、首尾随机缩短、检出概率抽取、按传感器周期插值、中断和加噪。上述长度筛选位于生成观测碎片之前，不是下载包内短片段删除规则。TMTAFF称遵循[48]，仍不足以确定其具体发布版本和生成器参数。批构造只明确场景顺序拼接，不能进一步声称每个batch完全来自同一场景；截短长度分布与频率未公开。

参考实现、候选及强控制须共用正式名单和评价人口，从头训练，并记录实际样本呈现、阶段更新与收敛情况。扩容后原样保留1000步不代表训练量已对齐，不能把论文80epochs直接换算成现有更新数。现有结果保留为开发证据；数量对齐亦不自动消除Level、窗口、过滤及评价定义差异。新名单准备不改变在途配置，不自动增加训练或打开测试评价。本轮已完成2400训练/验证场景的流式时钟核验与人口准备，并接入显式scene训练协议；新TCM有序完整遍历一遍需3356步。服务器全量训练的实际内存/吞吐尚未测量，数据准备完成不等于训练已完成。

## 不能漏掉的协议边界

- **预处理不同，不等于别人挑容易数据。** 上述短窗方法仍有噪声、漏检和密集目标测试；但多数关联论文没有承担我们全场长缺失物理恢复的全部任务。
- HTG-TA、MH-T2TA、TF-TS的问题定义假设同源不同轨迹属于不同目标，主要处理局部跨源对应。我们允许同源中断片段属于同船；直接把一对一指派套到全部碎片，会改变任务。
- TMTAFF明确包含同源/跨源全配对，不能用上述局部跨源论文反推它应做时间交集筛选或Hungarian。其原表PCA是召回、PFA是1−precision，不能拿论文数字直接比当前macro-F1；实际共同时间范围仍未还原。
- 已核原文没有可直接复用、并等价于本项目shared-A传递组件隔离的完整manifest。MIS明确场景隔离；“未说明跨场景身份隔离”不等于证明泄漏。MVW的test F1调参等做法也不应移植到我们的封存测试协议。
- MIS采样后的22822测试对与最终全候选指派评价的具体对应未说明；MVW另报20629测试样本，按场景划分不要求pair比例恰为10%，但具体数量对应未公开。不能把两篇处理后测试流程说成已完全还原。
- 论文“场景数、原轨数、配对数、窗口数、epoch”不是同一单位。我们T_core有54792条片段，与FESR的约44000、CA-LSTM的约76000已是同一数量级，但独立场景、窗口和呈现次数不可据此视为相当。不能只把512增成3000，就认定复现问题解决。
- 本地9001/reference复用是本项目已审原包的实证，不反推其他论文也复用了完全相同的输入与真值。

## 对当前任务的边界

**怀疑数据选择有道理，但目前更明确的是三项差异叠加：子集分布、任务范围和处理/评价协议。** 不能只归因为“抽到坏数据”，也不能用“任务更难”替代对本项目设计的修正。旧候选在已有支撑区仍劣于简单融合的[负结果](history/README.md)不因文献协议不同而消失；任务范围无法单独解释这些错误，当前修正版的真实能力仍需验证。

1. **子集代表性已有实证风险。** 我们训练前两个shared-A传递组件贡献91.87%轨迹；训练/V每场均值107.02/25.55、最大2372/99。TCM按轨抽样，配对训练按类→均匀场景→pair抽样，两者受组件/密度分布影响不同。详见[数据契约](data_contract.md#2026-10-19补充当前子集的代表性风险)。这是分布偏移证据，尚非低分因果结论；自然候选正率0.6068%不等于训练batch正率，后者正负各半。
2. **整场查询不是已经证实合理的论文复现。** 当前场景中位119.7分钟、片段24.5分钟；单片段被查询到自身支撑远端。多篇原文使用局部窗口、共同覆盖或有时间条件的关联，TMTAFF则明确全配对但未公开实际共同时间范围。须明确输入可见范围、恢复距离和评价人口；尚不能由其他文章推出统一60秒、21分钟或筛选候选就是TMTAFF的答案。
3. **清洗与表示可以借鉴，但先保留任务语义。** 我们已实现圆周航向、原生时间、合法监督mask与候选观测底座，不重复开发。MVW的删短轨、FLNN的保双源目标、TSA的真关联时间条件属于任务人口变化；不能偷偷照搬成“修bug”。要比较这些论文，可明示适用子集及覆盖，不能只给某个方法删难例或改标签求高分。

参考feature误差与候选物理误差须分表；已有补全诊断不能替代完整系统比较。当前结果与方法安排分别见[研究说明](research_brief.md)及[交接索引](../HandOver/Handover.md)，不在文献协议表中重复维护执行计划。改变分布、窗口、人口或指标须明确披露，不能按V分数换场景或给某方法单独删难例。
