## 冻结实施契约

| 项 | 060固定行为 |
| --- | --- |
| 唯一训练变量 | `configs/evidence-association-level1-3000.json`与056配置仅`training.updates`不同：1000→3000；full_evidence、seed20261021、普通均衡采样、batch256、lr0.001、验证间隔100、T2100/V300及全部输入/损失不变 |
| 开始方式 | 随机初始化后从头训练；只读056的COMPLETED final1000作比较，绝不加载其参数/optimizer继续训练，不增加resume框架 |
| 前缀核对 | CLI显式`--prefix-reference`指056关联目录；验证配置、人口、normalizer、step0 OLS与来源状态；1000保存当前权重/Adam、scores、阈值/指标与成功采样审计，比较056 final，不用selected |
| 数值差异 | 权重/Adam容差atol1e-7、rtol1e-5，scores容差atol1e-6、rtol1e-5；同时保留逐值一致、最大差、阈值/接受边变化和指标差异。数值不一致记录MISMATCH并继续固定3000，不调参；来源无效、人口/配置/采样策略或成功曝光审计错配失败，不自动修复重试 |
| 主终点 | 固定3000的final权重、scores、阈值与实际更新数绑定。selected仅原有边级辅助记录，不能换主终点，不因中间V结果调lr、早停、加步或追加实验 |
| 系统评价 | 复用056完整V300六臂：OLS/学习关联×Anchor/Mean supported/属性拼接，固定anchor_direct及原053纯OLS工作点，三种普通恢复不训练 |
| 跨轮比较 | 060与056原缓存逐场核同输入/真值/人口及OLS控制；比较三种学习分组输出的共同点、同/换代表、新/失覆盖及G/U/D，三属性误差与场景宏平均分开，不以条件MAE单列排名 |
| 预算 | 拟定一次单GPU/CPU4，从头3000更新、完整六臂评价及一次CPU缓存比较；整链2小时仅提醒，失败不重试，不打开T_test；最多四个获批单卡任务，可与现有三GPU任务并行 |

1000前缀只作复现核对，不重新运行一遍1000步系统；使用已完成056的系统缓存作基线。新增检查不消耗训练采样RNG，不从源checkpoint重建随机模型，不改变原训练选择规则。若前缀不一致，3000结果仍可作为该次运行事实，但不能全部归因于训练长度。

主要决策依据是覆盖—重复、同点物理误差及逐场表现，Macro-F1/mPCA/mPFA/FP作关联证据。若只边级F1好看而系统退化，不自动加步；若改善，说明本模型在当前开发协议下受到训练量限制，仍需结合059的同seed采样干预和后续独立验证，不宣称已超过TMTAFF或已完成稳定性验证。
