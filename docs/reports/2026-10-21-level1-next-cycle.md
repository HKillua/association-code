来自 Level2 **开发集**而非 Level1 的历史事实：045 学习关联 macro-F1 0.838840 对同输入 OLS 0.727170；048 替换关联分组后，普通融合位置 MAE 4391.52→3751.35m；043 学习补全位置 MAE 4815.48m 比自身 OLS 4737.76m 更差；049 正确组 TFM 100/300 更新出现近常量/常量输出；051 符号监督并未改善融合。不能将其解释为已复现 TMTAFF 或 Level1 效果。

## 二、A：完整系统（先建立评价闭环）

新增 `tools/experiments/level1_ols_working_point.py`：仅读取 V_select 原生量测与身份标签、零训练，按原 `select_threshold` 精确计算 pure OLS 几何工作点，写出与关联 step0 同 schema 的文件。此 V 阈值仍是开发集选择，后续不能在 T_test 重选。

新增 `tools/experiments/level1_system_evaluate.py` 为 **V_select 冻结评价入口**：

- Level1、场景划分、精确 T_core/V_select 列表和 canonical_all 策略必须匹配；不拟合 normalizer，不重选阈值、模型，也不打开 T_test。
- 纯 OLS 工作点来自当前关联 step0 的 `ols-working-point.json`；学习关联只能配套交付 `selected-scores.npz`、`summary.json` 和 `data_audit.json`，拒绝场景/节点/pair 次序变化。
- 普通融合为 `mean_supported`；可选融合 checkpoint（需配套 `run.json`）提供学习融合。形成最多四臂：OLS+普通、学习关联+普通、OLS+学习融合、学习关联+学习融合。
- 片段视图报告点加权 MAE/RMSE、场景等权 MAE、覆盖及原始观测支撑内外/远时距。唯一目标视图复用项目 `evaluate_full_scene` 和 `aggregate_fusion_reports`，直接从完整 `fusion_targets` 及原始标签身份列表加载真值，连无有效输入身份也计入分母；对不同方法再用共同有效目标点进行逐属性、逐区域公平比较；严格保留漏目标和重复输出，不按标签挑 anchor。
- `summary.json`、逐场结果、片段预测与全部目标对齐数组（含 group membership、offset、重复预测组、路由、真实值、逐属性有效掩码）分文件保留，支持复算；融合必须加载与 `run.json` 更新数/配置完全一致的正式终态 checkpoint，报告真实 step。本地集成时复用了现有 loader 并增加 `validation_only=True`，只读取完整 V_select 的量测/标签/reference，不再加载 T_core；默认训练加载行为不变。`preparation.json` 和逐场 `run.json` 记录实际读取及进度。

**验收**：先用零训练工作点工具取得当下纯 OLS 工作点，然后运行不带学习 checkpoint 的普通完整链；同一个 V300 人口上比对 OLS 关联记录/普通融合；再带已完成学习关联和融合的输入逐个替换，任何 checkpoint/划分不符都拒绝。必要的回归测试请在服务器真实环境运行；当前没有 Level1 数值结果。

## 三、B：TFM 的一次有界定位

新增 `tools/analysis/tfm_information_probe.py`：从原049的固定V场1671、2056、290、113各按候选顺序均匀取2对，复用049输入adapter和normalizer导出2–8对TCM latent，保存输入来源；也接受外部 `left/right` NPZ，但无来源时标明未知。使用已存在的049快照0/100/300和033来源权重，冻结执行，无reference读取或optimizer更新。通过临时 forward hooks 记录左右 encoder、FC1、FC2、64 步 decoder 最后 token、state_projection、最终物理状态的样本间/时间内 RMS 波动及两输入对的响应。

这只是 **现象定位**，RMS 不能解释为信息损失百分比，更不能自动认定某层是因果根源。

导出和探针已在同一入口中实现，服务器执行命令即可；固定候选顺序取样，不按身份真假、reference或误差挑选。记录原场景/节点和实际快照游标，核TCM参数与normalizer一致；不筛掉latent近常量输入。分别运行原配对、固定左侧替换右侧、固定右侧替换左侧，检查是否忽略某一路输入。

**判断分支**：
1. TCM latent 已近常量：排查上游补全编码和 token/时间输入，暂停 TFM 结构猜测。
2. encoder 前有变、FC memory 无变：定位 FC 输入压缩/权重/归一化，并用两输入替换响应做一个最小确认。
3. memory 有变、decoder latent/physical 无变：重点检验缺失 query-time 位置条件、自由生成退化和物理锚点，形成一项小修候选。
4. 输出正常变化但验证常量：检查诊断输入、保存预测/快照映射、推理入口和输出采样一致性。

一次诊断不能定位则如实写“未定位”；不自动开启任意新训练。

### 目前仅建议优先测试一个核心问题

**关联边的判别正确性和帮助最终物理估计的效用不是同一个对象。** 当前 associate→group 将连续 pair score 硬阈值化，融合器只收 groups 与运动证据，不使用关联 score 或可信度。这一结构性断点清楚且可定位，但尚无证据证明“引入 score”一定有效，也未证明此前工作没人做过。

研究假设：在相同输入预算、相同网络容量/训练规模及公平分组条件下，将可校准的关联风险或实际混合增益用于 helper 接纳/逐属性权重，有机会减少错误 helper 传播和支撑外的物理损害。

实验必须先核：
1. Level1 上先分别报告 OLS 和学习关联产生的错误 helper、普通融合误差。学习关联 F1 不是设计新融合方法的硬门槛；若其增量不成立，仍可在固定 OLS 分组下检验可靠融合机制，但不声称关联贡献。
2. 旧 051 拒绝的 helper 中真实“混合有益却单源无益”的比例是否足够高；若很少，不以该现象立项。
3. 比较不传关联分数、传原始分数、经训练/V合法校准的分数；须有匹配容量的同输入控制。若仅分数排序换了阈值导致提升，不声称新的联合机制。
4. 旧 048/051 的 V 已反复开发，正式测试只允许最终方法冻结后一次评估，多种子并说明跨场共享身份造成的相关性。

**明确不做**：虚称真实 radar/AIS 多模态（MTAD 样本是 AIS 基础处理所得）；把 OLS 改良算学习贡献；用 Level2 单 seed 先导证明 Level1 新颖性；靠修改 mask、删短轨或缩 query 区间制造增益；把论文不同人口指标直接换算成“超过作者”。

## 五、下一执行周期的先后与停线判据

- 并行 A：先验证 Level1 纯 OLS/普通融合 V300 评价是否能跑完，生成完整人口、片段/唯一目标及共同目标点报告。不满足输入/身份覆盖时停下报告，不静默跳场。
- 并行 B：049 纯冻结前向逐层响应，单独观察位置、速度、航向是否坍缩；即使 TCM 输入已近常量也出报告，不再训练旧 Level2；形成“响应断点在哪/未定位”的记录。
- 并行 C：持续核对可投稿性与反例，明确区分关联正确性、实际混合增益与最终目标误差；不要求 Level1 学习关联胜出后才开始设计融合改进。未经核实的 SSRN 条目从当前引用排除。
- 后续训练：当 A 路径可信、服务器 Level1 原件齐全且用户批准预算，再分别申请关联 fit 与一个融合 pilot；不将某个网络的 F1 增量作为另一网络研究的硬前提。
- 决策：仅当有证据表明与普通/匹配容量对照相比，关联分数提供额外的可靠融合收益，才保留“关联风险联动”作为贡献；如果单纯 OLS 分组下的融合收益存在，可先写成独立可靠性方法。不能把 TMTAFF 失败作为胜出依据。
