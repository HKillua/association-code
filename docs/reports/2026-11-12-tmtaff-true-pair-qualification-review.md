# TMTAFF 固定16真对的短程训练资格

## Record · C90 原尝试

上游方案是 `IDEA-TMTAFF-COMPONENT-QUALIFICATION-20261111` v1.0 的第 B 节执行版。问题是同107 TCM与同一批真对输入下，速度与航向监督是否制约TFM学习位置。A用四属性目标，B只用原经纬损失及其可学习权重正则。样本为固定153的8个训练场、16个跨源真对、27个节点出现和1,024个pair-query。纬、经、速、航有效数为732、732、729、732，位置支持按双源、单源、零源为301、299、132。普通控制与历史预测使用同一Q64、同一参考与掩码。两臂固定u0/u16/u32，资格判断只用u32。[冻结方案](../proposals/tmtaff_component_qualification_20261111.md#c90--固定16真对的短程资格诊断)

执行中发现两臂实际Adam使用默认 `betas=(.9,.999), eps=1e-8`，与原计划保留的107设置 `(.85,.99), 1e-6` 不符。在200.553秒处只停止本任务。最后可核对的落盘是各8步，至少各128次pair呈现，未保存u16/u32或最终门。详细命令、进程和聚合原件见 [C90中止回执](../../HandOver/S2L-20261112-c90.md)。

## Squeeze · C90 原尝试

原107 checkpoint的保存状态与项目共用工厂 `association.training.common._optimizer` 参数逐项相同。故障来自新增入口绕过工厂，以及输入预检未绑定实际optimizer参数组。受影响的是复现实验协议与从原107迁移结论的有效性。相同默认Adam的两臂比较本身也只有初始时刻的完整固定评估，无法评价联合目标影响、训练资格或泛化。

保持旧运行及输入证据，独立修复入口复用原工厂，并在启动任何更新前核完整参数组、参数数量、零优化历史、原固定学习率和clip设置，以及两臂逐值同初始化。修复重做原已登记问题，不用中止运行的信息改样本、步数、比较臂或判据。[修复合同](../../HandOver/L2S-20261112-c90-r1.md)
