# 数据、baseline与实验学习清单

当前正式数据改为Level1，过去Level2实验只作理解方法和故障的案例。完整旧清单可从清理前404d766查阅；实际任务以[交接索引](../../HandOver/Handover.md)为准。

## 阅读顺序

| 内容 | 材料与自查问题 |
| --- | --- |
| 研究目标 | [研究说明](../research_brief.md)：补全、关联、融合各解决什么，哪些贡献已获证据、哪些仍待验证？ |

## 建议的一天安排

1. 上午先画数据流：原生CSV→清洗节点→场景划分→query/目标→补全→全部候选关联→分组→融合评价。手算一对正例、一对负例及一个没有合法监督的query。
2. 午前读TCM/TAM/TFM代码，逐个写输入shape、是否读取真值、训练哪些参数、推理输出什么。说明为何特征MSE不能直接说成补全位置米误差。
3. 下午读043、049与051分析。区分程序正确、训练完成、物理效果和机制解释；用相同有效点重述一个对照，列出被保护的来源/属性/时距。
4. 最后整理一页汇报：一个最可靠正信号、两个未解决故障、下一项最有区分力的实验及其失败后决定。使用已有证据，不把独立模块数字拼成完整系统。

## 需要能解释的几个例子

- 049在正确身份组也输出同一位置，为什么不能主要归因错关联？两片段也失败又排除了什么？
- 043换OLS底座整体好很多，却比自身OLS差，为什么换底座收益不能算学习创新？
- 045的边F1改善，为什么还需要048固定融合器换组？
- 速度真值30、anchor40、helper10，helper单独更差却能以1/3份额消除偏差；这对当前效用标签意味着什么？
- 两方法覆盖点不同，为什么要同时报各自覆盖和共同有效点？零交集为什么应为null？
- Level1和Level2共享身份、同编号场景不同，为什么不能直接把一个包当另一个包的独立测试？

## 后续动手范围

先核Level1三个分卷的可读入口，再生成其自己的固定名单、时间映射、训练统计和人口记录；Level1 scene0留训练侧。模型从头训练，旧Level2权重只用于明确的故障定位，不当新数据基线。新增训练按具体方案与交接执行，学习过程不自动扩训练预算或打开测试。
