# MTAD 训练协议修订 v2

2026-10-17 用户在全文调研后明确要求“可以的，修改吧，我们如何改我们的实验”。本版本落实训练修订；它是独立关联参考的实验设计，不声称还原作者未公开的训练器，也不启动完整多种子实验。

## 问题与修订

v1 的 T_core 含 18,249,384 对，每轮 285,390 次 TAM 更新，80轮合计22,831,200次。008最大场景的6步平均152.61秒，但这不是全训练集速度。主要问题同时包含组合爆炸、极稀少正例和从随机补全开始的长自回归反向传播。文献支持考虑平衡采样和分阶段训练，不能证明任何统一最优比例或固定训练轮数。

1. 保留007的共享A组件划分、A–B身份标签、同源/跨源候选、length64注册、归一化输入、FP32和6层/128维模型。原prepared manifest/audit保持原样，新训练配置另存hash。
2. 训练每批64对，32正例+32负例。对每个类别，先在含该类的训练场景中均匀选一个，再均匀抽32个原始候选对；不足32个才有放回。两类可来自不同场景，绝不构造跨场景对。单类场景仍参与相应类别；同源正例不删除。该目标是“类别平衡、类别内场景均匀”，不是原v1全边平均，也不冒称所有场景严格等权。
3. TCM独立预训练保持固定input embedding及原教师强制双向补全损失；TAM阶段冻结embedding与TCM并将TCM设eval，只更新TAM及分类头；joint阶段重新开放embedding/TCM，使用关联损失+0.1补全损失。各阶段重建Adam，采用显式固定学习率，避免把旧epoch调度误搬成update调度。
4. 冻结阶段可在本次运行内、CPU内存上限内LRU缓存 `complete()` 的FP32输出。TAM始终重新计算并反向；cache构造绑定当前模型对象/归一化场景，只存在于冻结阶段，joint前销毁。禁止跨更新缓存可训练模块，禁止从磁盘复用未核验特征。
5. 以优化器更新数设上限，独立记录每阶段步数与耗时。正式fit按固定update间隔及阶段末对完整V_select选模，宏F1、阈值规则与原协议相同；tie保留最早checkpoint。不得因成本改用采样验证集。所有正式缓存写完才可判定参考完成，超时保留失败证据，不把部分训练当已收敛模型。

## 先执行什么

新入口 `probe-training` 只用于三阶段流程与成本验证：T_core、A0、CE、seed20，TCM 8步、冻结TAM 4步、joint 2步，合计14次更新，进程总上限30分钟（含读入/准备/缓存），重试0。模型和64对批量保持正式尺寸，cache上限64MiB。阶段间共享当前权重，故耗时差不是冻结的严格因果对照。每步保留原始loss、grad、类别与同/跨源计数、唯一端点、缓存命中、耗时、显存，记录各模块阶段前后hash；不读V_select/T_head/T_test、不选阈值、不生成可被正式pipeline复用的checkpoint。

009仍是当前只读取证任务；本轮不覆盖009、不发布并行010。用户随后要求先搞清官方Level1/Level2及各论文实际数据用法，新增数据定义复核前置门。009终态且数据用法审查完成后，由本地核验原件、确认具体执行范围，再创建独立L2S及确切已存在code_commit，才允许服务器执行新probe。Git push不唤醒服务器AI。此处30分钟是后续有界交接的候选上限，不与旧轮次预算混用；配置文件存在不构成派发。009的原请求对association/configs等目录实行整目录冻结，即使READY状态也不能向main提前合入本版本使其领取检查失效；代码先保存在独立分支。

正式训练先做一个A0/CE/seed20开发fit，再决定是否扩展A_full、contrastive和三种子；不得直接启动旧8-fit流水线。供成本核算的候选上限是TCM1000、冻结TAM2000、joint100更新，完整V_select每500关联更新及各阶段末验证。该规模仅用于可审阅的计划，不生成默认可执行完整实验配置或扩大授权。真实probe回来后先核总时间、完整验证/缓存成本、TCM学习曲线及短支持轨迹补全，才能冻结正式fit预算和配置。仅通过14步不证明收敛。

## 后续比较及边界

- 第一道关：流程、梯度、类别、冻结与缓存合法；出现NaN/OOM/超时即停，不降模型规模或自动改精度/批量。
- 第二道关：补全预训练确实学到东西，关联在训练/完整验证上优于全拒绝，学习曲线和误配率合理；只报告F1不足以判定可用。短支持、同源/跨源分别审查。未来随机端点截断增强须另设版本；本次不以“修复”名义混入未验证增强。
- 最小归因对照：在固定场景/预算规则下比较自然比例有界抽样与1:1抽样、全程joint与分阶段冻结；若采用2×2，需明确TCM预训练共享条件及update与wall-time两种成本，场景权重变更单独披露。不重新跑已判不可行的80轮全边v1。
- 对照参照先可靠，再回到CDF1及其必要消融；所有方法共用训练分布/输入范围/验证选模预算，T_test封存直到全部选择固定。没有TFM，不能声称完成TMTAFF全部复现。
- SCTA-Net暂缺不阻塞本次修订；不再为了持续推进追加阅读或无关探测。

## 软件契约与验收

新增schedule显式选择`staged_updates_v2`；旧配置仍走原路径。probe配置被train-reference/run-pilot/profile拒绝，防止把诊断配置变成正式实验。v2加载失败/预算耗尽留存终态、历史和原输出；已有输出拒绝覆盖。正式fit的joint从完整V_select选出的最佳冻结TAM快照开始；最终在预声明的TAM/joint快照中择优，平分保留更早快照。显存逐步记录的是进程累计allocator峰的快照，不是独立step峰或整卡占用。

|ID|可观察标准|核验|
|---|---|---|
|V2-1|每个关联batch恰好半正半负，pair来自原训练场景，同源正例和单类场景可被抽到|sampler fixtures、seed复现、缺类拒绝|
|V2-2|TCM阶段embedding/TAM不变；冻结TAM阶段embedding/TCM不变；joint有真实TCM/embedding/TAM梯度|真实小模型参数快照和梯度测试|
|V2-3|缓存值等同未缓存complete输出，TAM更新不被缓存，容量有界，joint不读缓存|梯度/输出/容量/阶段失效测试|
|V2-4|probe只加载T_core（A0），无验证/测试/参考轨迹访问，无eligible checkpoint|真实合成archive读取追踪、加载器拒绝|
|V2-5|fit按更新选择完整V_select、保留原阈值和tie规则，正式cache与hash匹配|小模型端到端fit/reload/cache测试|
|V2-6|旧config/旧训练行为继续通过；v2诊断不能由旧入口静默执行|原测试集+CLI负例|

本地验证：131项主测试、39项setup测试、15项旧Level2审计测试均通过；真实合成ZIP经CLI完成五步三阶段probe，旧train-reference/profile入口按预期拒绝probe配置。另有实际小模型fit→完整V选择→cache→reload测试，SIGTERM与预算失败、缓存输出/梯度等价、阶段参数冻结、复现抽样均通过。CPU环境为Python3.12.14 / torch2.10.0 / numpy2.5.4；没有本地真实CUDA或正式MTAD训练结果。独立审查修正了失败落盘遮蔽原异常及逐步显存证据遗漏，见[复核记录](../staged_v2_independent_review.md)。
