# TFM物理输出尺度修正

2026-10-18；状态：按用户“找到问题直接改代码”的最新授权实施本地修正，不授权新增GPU训练。证据见 `docs/results/tmtaff014_local_review/`。

014的358个真实身份多轨组全部出现千万米级误差；42个二轨组同样异常。当前最终LayerNorm之后直接线性输出原始经纬度，Xavier零偏置初始化与Adam短更新量不能迅速跨到约131°的经度区域。它是当前近似实现的数值参数化与训练方案冲突，不能冒称查到了作者代码的缺陷。

## 行为与范围

增加显式 `PairFusionConfig.output_parameterization`，允许 `raw`（默认、历史行为）和 `train_position_affine`。017正式参考配置已选择后者并获得独立预算；本页不授权新训练或改动017活动配置。

`train_position_affine`仅将经纬度投影 z 按仅由T_core原生输入拟合的固定统计量恢复 `position = z * std[:2] + mean[:2]`。速度沿用原raw投影softplus，航向沿用原raw投影，不用速度/航向mean/std。连续SmoothL1、速度/航向损失、损失权重、TCM/TAM、分组递归、参数规模、数据/标签/采样/选择规则不变。不增加经纬度裁剪、不用V/reference拟合尺度、不改历史运行或候选实现。命名为“TMTAFF时间与输出尺度适配近似参考”，不是原作者精确实现，也不是创新模块。

经纬度的两维统计量作为不可训练buffer保存；新训练由既有normalizer传入，selected/last快照和训练恢复均从检查点的同一normalizer及state恢复。传入normalizer必须为四维、有限且std严格正；保存buffer仅取经纬度两维；缺失/错误统计量不能退回raw或默认尺度。原始模式的state_dict形状与数值行为保持不变；旧fusion_config缺该字段等价raw，旧检查点可以评价/按原恢复规则恢复，不能自动升级参数化。

| 只依赖训练统计且参数规模不增 | normalizer输入校验、buffer不可训练、模型参数计数相等，保持原生参考标签不参与统计 |

| 研究边界与预算 | 013/014及015历史配置不改；未来运行只按独立已批交接执行 |

## 限制

该修改只消除输出远离地理范围的确定数值障碍，不证明关联改善、补全准确、候选效用有效或参考已收敛。legacy候选018采用四维mean/std输出映射，当前v2已改为[独立表示规格](../proposals/candidate_revision_after018/representation.md)；参考仅对经纬度适配，比较须披露差别；两系统仍有优化器、loss、选模、singleton等差异。历史014结果不重新解释成修正后结果，不重跑。完整训练量与资源仍需真实成本和另行预算决定。

独立复核确认应限于位置：真实速度mean约109、std约415，全维affine会将速度投影−1送到softplus约−306，FP32局部梯度可为0。最终实现不新增这个速度缩放；当时未改候选映射；016随后确认015预测为大正速度而非压零，当前v2另按已批准规格修正速度参数化，不能将本页反例当作真实压零证据。
