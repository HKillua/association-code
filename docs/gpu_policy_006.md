# GPU-POLICY-006：动态选卡与共享 GPU

日期：2026-10-17。用户直接授权：“不一定固定的是哪张卡，也不一定不能共卡，能跑实验就行。”本规则替代旧轮次“整卡空闲／存在 compute 进程就拒绝”的资源准入要求；旧回执保持原样。

## 已知事实与范围

ENV-005已通过CPU和真实CUDA验收。服务器最新提交f8b34eb记录：合成pilot为34.02秒、进程峰值分配18500096B（约17.6MiB），在当时空闲的GPU1上运行；内外rc=0、COMPLETED与报告hash一致。CPU与CUDA实际提交不同但源码/环境一致，旧HEAD误拦修复已实际验证。此次没有共卡，不能宣称共卡已实测。

本轮只更新资源调度并同步政策，不重新安装、重跑CPU/CUDA，不改模型、训练/数据逻辑、测试标准、版本pin或精度。新增helper本地回归；服务器只做一次有界只读查询。后续正式数据准备/profile另行下发，继续保持ENV-005已通过结论。

## 行为规格

| 条件 | 行为 | 检查 |
|---|---|---|
| auto选卡 | 实时枚举设备，剩余显存最多优先，利用率低与index作同值排序；不固定0..3或型号 | 多卡快照单测 |
| 明确卡号/UUID | 支持任意非负index或可见GPU UUID，实时验证存在并按UUID绑定 | 非0..3及UUID用例 |
| 卡上已有他人进程 | 允许共卡；进程快照用于记录，不作为拒绝条件 | 所有候选都有compute进程仍选择 |
| 卡负载较高 | 不设利用率硬门槛；现场可按吞吐/剩余预算选其他候选 | 选择与报告用例 |
| 显存估算 | helper默认仅要求有正的剩余显存，不杜撰smoke已测峰值；现场可用实测或估算设置筛选参数 | 零显存和自定义估算阈值负例 |
| 设备信息查询失败/没有满足要求的设备 | 返回明确非零并保存证据；不能把未知设备当成功 | 查询失败/空结果用例 |
| 进程信息查询失败 | 记录unknown与退出码，设备资源查询有效时仍可选卡 | 进程列表不再是准入门槛 |
| 启动 | 当前只用一张卡，CUDA_VISIBLE_DEVICES绑定UUID；cuda:0是进程内逻辑编号 | 驱动接口与产物验收 |
| 显存竞争/OOM | 保留失败，释放本轮进程后，可在总预算内同配置换卡；CUDA最多3次尝试 | 交接预算、输出不覆盖 |
| 科研错误 | NaN、代码/契约失败停止回报，不通过减batch/改精度/跳样本掩盖 | 原科研检查保持 |

选择时的GPU型号/UUID/显存/利用率和进程信息单独写allocation.json，不加入CPU环境相等字段，换卡不会使CPU凭据失效。通过只证明实际CUDA流程完成，不证明独占吞吐；共卡耗时受竞争影响，应保留现场上下文，不直接作为独占benchmark。

## 授权与本轮执行

服务器可以自主选择、共卡、在资源故障后换卡，无需为普通设备选择再次请示；不终止他人进程、不改系统驱动。后续GPU任务各自固定预算内最多3次资源尝试，不因换卡或重启计时而加预算；不改变batch/模型/精度/种子来应付资源竞争。存在其他compute进程不构成等待理由，真正没有满足资源条件的设备时才按本轮等待预算观察，不建后台监控。

本轮GPU-POLICY-006只同步新规则，最多5分钟现场核对和一次helper查询；查询不是CUDA负载、不占卡，不能把查询成功当实验成功。只读资源证据写入GPU-POLICY-20261017-006，不改ENV-005回执及产物，不额外重跑CPU/CUDA。之后准备真实数据与正式配置profile交接。

## 验证记录

本地95项项目测试、15项旧审计通过；32项setup回归包括共享设备准入、任意index/UUID、负载排序、查询失败分类、CPU证据复用和信号处理。新增helper仅做模拟nvidia-smi测试，尚无真实共享负载执行；服务器ENV-005是在空闲卡上通过CUDA，两个结论分别记录。
