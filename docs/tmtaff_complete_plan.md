## 2. 两项损失选择及推荐

**CL：保留原距离，先确定margin来源。** 原文p.11 §2.3.1 Eq15给出欧氏距离和正项一次距离，但没有公开m数值，也没说明表征L2归一化。旧scene64初始化反例只能证明默认m=1存在风险；新的时间输入已变，旧距离59.75/67.82不能用于填写新m，也不能用来解释未使用CL的011低分。

推荐先在固定训练侧配对、明确的TAM起始状态上报告正负距离、负hinge激活比例及分项梯度，再一次确定m并写入正式配置。可审阅的候选规则是：固定seed和配对样本，在TCM预训完成、TAM未更新时，用训练负对距离中位数定m；ties和实际激活率另报。它通常让约一半负对处于hinge内，但不保证梯度平衡或好效果，不能按V/T_test结果挑m。**规则、样本规模及所需实现/预算尚未批准；现有CLI不支持阶段内自动校准，不能声称命令已可执行。** 初始化CPU诊断只能提供起点风险，不能代替TCM后的尺度。

备选是RMS距离或单位向量距离，但当正项为一次距离、负项平方时，缩放距离会分别按1/c和1/c²改变两项，绝非简单换单位。这会额外改变方法，首版暂不推荐。直接硬填64/128也缺乏当前timed模型证据。

**位置loss：推荐连续SmoothL1，保留印刷版本供追溯。** 原文p.15称其为SmoothL1，Eq20印刷写内支 .5r²、外支|r|−5×e⁻⁴、切点10×e⁻⁴。按本地科学记数解释δ=.001，切点两侧分别约5×10⁻⁷与5×10⁻⁴，函数不连续；若e指自然常数，仍不连续。作者代码与记号含义尚未确认。

| 选择 | 明确公式与后果 | 建议 |
| --- | --- | --- |
| `standard_smooth_l1(beta=.001)` | 内支 .5r²/δ，外支|r|−δ/2；函数与一阶导连续；保留本地δ和外支 | **推荐**，符合原文名称，但须称解释性修正、由用户确认 |
| `paper_printed` | 保留当前印刷科学记数解释；切点跳变 | 保留实现/历史，不推荐直接主训 |
| Huber δ=.001 | 内支 .5r²，外支δ(|r|−δ/2) | 与SmoothL1差δ倍尺度；Eq18可学习权重不保证消除差异，不自动追加 |

只改位置loss的选择，保留Eq18权重、航向及速度loss；不顺手换地理坐标、状态归一化或增加噪声。用户确认前不改正式配置。论文事实与疑义对应[综合审计](experiment_reaudit_20261018.md)、[TFM约定](specs/tmtaff-fusion.md)。

## 3. “完整四阶段”不等于训练充分

现采样器每次TAM/joint更新只为每个类别选一个eligible场景。某类有S个场景时，K次更新后该类场景的**预期已访问比例**是 `1−(1−1/S)^K`。以S=512作算术示例（不是实际eligible计数）：

| 该类场景抽取次数K | 预期访问比例 |
| --- | ---: |
| 100 | 17.76% |
| 500 | 62.38% |
| 1000 | 85.84% |
| 2356 | 99.00% |

TFM每步也只选一个正例eligible场景，因此旧500TFM更新并不能声称覆盖全训练池。以上是期望、不是保证；访问一个场景也不等于见过全部身份、轨段或候选。TCM64轨随机批同样不能将“呈现N条”称为“每条恰好见过一次”。不能为了补覆盖擅自改为遍历采样；应先读实际coverage，再把训练量和成本一起决定。

首个实验应准确命名为“完整流程的开发预实验”，报告四阶段实际更新、独立轨迹/场景/配对覆盖、曲线、最终全目标结果和计算代价。论文80epoch细节不足，不能拿固定100步代称复现充分，也不能仅凭预期99%访问就宣称收敛。候选必须与同输入、数据并集、优化量及阈值口径的主参考对照；现有CDF负结果不触发继续训练。

## 4. 成本证据、测量方案与当前边界

完整CL＋TFM(h128)＋loss权重共8,720,136参数，FP32权重33.26MiB，权重/梯度/两Adam moment静态133.06MiB。**这不是显存峰值。** 新TCM native history最多128，外推decoder继续增长；TFM64步重复处理累计2080个decoder位置，不能用参数比例换算GPU时间。

旧010 RTX3090外层7272秒、峰值分配10.38GiB；旧CE阶段摊销TCM/TAM/joint为3.045/17.484/94.979秒。A_full逐步均值2.744/18.379/102.149秒，两次验证552.80/539.94秒。机械代入旧500/1000/200得到10.56或11.16小时，**均不是新系统总成本估计，也不是可信下界**：没有TFM、新时间适配、完整融合评价等成本。原件：[010摘要](../HandOver/results/COMPARE-20261017-011/reference010/summary_metrics.json)、[A_full history](../HandOver/results/COMPARE-20261017-011/afull/files/history.json)。

完整费用必须拆为：CPU原生/参考准备＋TCM更新＋TAM冻结缓存填充及更新＋TFM更新＋三模块joint更新＋每次完整V关联选模＋最终预测/oracle全目标融合评价＋checkpoint/导出。`history[*].seconds`只给更新段，不能把验证/写盘遗漏；缓存首次填充不能当稳定命中耗时。误分组改变最终递归次数，初始化模型的终评时间不保证代表训练后。

从现存010的64场景V缓存独立复算：1635轨、377个场景内身份组、29008候选对。oracle递归融合需**1258次TFM调用**，预测分组侧最多1571次，两侧最多2829次；每次均为batch1的64步自回归，而不是“64个场景只跑64次TFM”。这是旧缓存几何而非新适配人口或实际耗时，见[计算证据](results/tmtaff_cost_geometry_20261018.json)。最终融合评价可能比8个训练更新更耗时，必须纳入预算。

不新增profile框架，拟复用现有完整CLI作**一次、四阶段各2更新、最多1 GPU小时**的全尺寸成本测量。此数是拟申请的资源上限，不是预测耗时或已经批准的预算。具体方案：

- 模型、有效batch、microbatch沿上表最终确认值，`updates`四项均2，`validate_every_updates=2`，测量用`lr_schedule=constant`以免2步余弦的第二步LR归零；种子20、CPU线程4，单个GPU作业，允许共卡，失败/超时不自动重试。
- 包含两次完整V关联选模和最终一次完整全目标融合；不删场景、不跳终评冒称完成。内部`max_hours=1`含准备、训练、验证和写盘；外层既有`timeout`工具在3570秒发TERM、再给最多30秒清理后终止该作业，总上限3600秒，不终止他人进程。
- 输入对齐和loss确认后，将具体JSON与原manifest/映射文件配齐，再使用已有`tools/experiments/tmtaff_complete_fit.py --archive ... --manifest ... --alignment ... --config ... --output <新目录> --device <当时兼容GPU> --cpu-threads 4`。当前没有这些正式参数文件，不发布可领取命令或READY。
- 可能在前两阶段/完整V耗尽，不能保证拿到TFM或joint步时。两次更新也不能估计P95、收敛或稳态缓存；已COMPLETED的测量和FAILED超时都不通过修改配置偷偷续成正式训练，正式训练额度另计。
- 当前CLI有总耗时、训练更新耗时、最终评价耗时/TFM调用数，尚无CUDA分配峰值和逐次验证耗时。不能从nvidia-smi少数快照推断训练峰值；如审批需要这两项，只做必要的小型计时/峰值记录补充，另行代码测试，不扩建框架。

这会产生真实训练和验证开销，**必须单独获批**；不拿012复制预算或011结余支付，不为凑阶段换更小模型。

当前没有新GPU实测，因而不能诚实给出完整训练总时长区间或保证12/24小时够用；也不能把请求的测量上限叫作预测耗时。完整候选配置/成本尚未确定，不能虚填0。先把损失解释与输入/监督配置定清，再给测量命令与明确累计上限供用户决定，测量后再决定完整训练额度。
