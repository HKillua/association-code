## 科研与创新

- **每次科研实验都完整遵循用户指定的[飞书《视频文案》](https://my.feishu.cn/wiki/OHs3w9meHiQ3OXk4XC7ctFPXnxd)和[本路线完整流程](docs/research_workflow.md)。** 基线复现、探索、诊断、回放、消融与留场均适用，包括本地只读复算和 CPU 实验。采用[仓库研究技能](../.agents/skills/README.md)，用户指定其他版本时按指定版本使用。
- 执行前关联来源分析、Mode C 与 Idea，事前固定问题、对照、数据权限、指标、预算、停止和回退条件。先读清机制、条件和反例，区分作者主张、直接证据、推断与未知。执行后保留全部运行及偏差，完成 Record → Squeeze → Mode C。按真实记录标记历史缺项与发现性探索，禁止事后倒填 Idea。
- **创新看明确的新增价值与发展空间。** 通过相似工作定位差异和适用条件。已有先例与成熟机制的合理海事适配均可继续研究，具体比较是否解决已知不足、改善效果或效率、满足新需求，或提供更有效的解法。初步想法写明可怎样深化及如何检验新增价值。按完整流程用对照与消融验证机制，核局部收益对整体、尾部、覆盖与代价的影响。无新增证据时结束当前配方。
- 研究覆盖输入、时序、关联、四属性融合与恢复，优先精度，速度作为代价。只按适用协议报告原文结果、可核复现或 MTAD 适配。遵守[数据约定](docs/data_contract.md)和[指标协议](docs/mtad_data_protocols.md)，封存 T_test，保留难例、全人口、覆盖、重复、尾部与场景／组件结果；开发对照、失效适配及软件模拟各自限于实际证据。

## 执行与保全

- 用户已授权本地研究、开发、必要核验及提交推送。新实验按[服务器规则](docs/server_autonomy.md)发布独立 READY，由服务器托管并回传。最多四个单卡作业，现场 FIFO，可兼容共卡。冻结活动配置和目录，一次尝试，失败保全。墙时为建议，保持冻结预算；本地不做 SSH 值守、守护或跨聊天／外部发消息。
- 核实际命令、退出、输入、配置和结果。Git 用于定位历史。保护他人修改，禁止强推。工程整理须保持模型数值和实验合同，删除旧工具前查调用、导入及权重加载，保留生产仍用的旧模块，只核受影响的链路。
- **保留独有研究证据。** 原文和阅读分析、矩阵 P/F/M/E/C 与版本、迁移条件、Idea 推导与未采纳依据、Record/Squeeze、反例、偏差、失败和未知均须保留。先核正文及来源链接已完整承接，再精简入口。保留原 ID、数据、真实权重、服务器运行原件及未审结果。
- 结案从[历史索引](docs/history/README.md)定位，未筛设计归现有历史导航。可移除已承接的重复回执、产物与闲置工具，按 Git 单文件恢复；资料库保留文献及其独有证据。无明确待办时结案。
