- **目标/结论/下一步只在研究状态维护，领取名单只在HandOver维护。** 不再在README、记忆、台账复制实时快照。旧材料按问题定向读取，不把全部历史灌入当前上下文。
- 从本目录运行[工程入口](README.md)，按本路线重新选型。只加载[本路线文献与证据](/Users/a1/Projects/biye-ronghe/offline_observation/README.md)和适用的公共数据来源。跨路线证据仅在任务需要时显式引入，代码和实验入口保持独立。
- 不要把整理字段和包名当研究进展；读清来源机制、条件、消融与反例后才建矩阵。

## 科研方法

**每次科研实验都必须完整遵循用户指定的[飞书《视频文案》](https://my.feishu.cn/wiki/OHs3w9meHiQ3OXk4XC7ctFPXnxd)和[本路线完整流程](docs/research_workflow.md)。** 基线复现、组合探索、诊断、消融、回放与留场均适用，包括本地只读证据实验、CPU 和服务器运行。

- 执行前关联本次来源分析、Mode C 和 Idea，明确要判别的问题、信息权限、基线与对照、指标、预算和停止／回退条件。各阶段可引用经核实的既有证据。
- 执行后保留实际配置、原始证据和所有结果，按 Record→Squeeze→Mode C 回流。探索性实验标清性质，历史缺项按事实标记。

常用技能统一维护在[仓库根目录的技能目录](../.agents/skills/README.md)。用户未指定其他版本时，从中读取对应 `SKILL.md` 及必要引用，同名全局副本不混读。用户最新要求、本文与完整流程优先于通用技能默认建议。

`analyze-paper → 来源分析 → deep-read Mode C（P/F/M/E与P×F）→ discover-innovation → Idea → 实际执行 → record-experiment → squeeze-experiment → Mode C回流`

- 先独立读懂原文，再讨论借鉴；作者主张SC、直接证据DE、推断AI、未知UN分开。不能先定方案再找依据，连接点也不能冒充完整Idea。
- 观察→归类→追问→机制假设→替换/分离→消融/核因果。追问、loss下降和软件检查都不证明根因或真实效果；局部收益须核整体、尾部、覆盖、异质性与代价。
- 跨域核A问题、B机制及条件、C迁移经验；必要时先建立A′，再比A/A′/A′+B。缺C如实记，不无限搜索；成熟机制与海上适配可以研究，不要求各模块原创。
- **创新判断以明确的新增价值和发展空间为重点，不追求“绝对原创”或“从未有人做过”的完美idea。** 已有相似工作或相关尝试不意味着方向失去价值，不得仅以“已经有人做过”过度防御性地否定或结束讨论。应具体比较：能否解决现有方案不足、改善效果/效率/体验、满足新需求、从新视角重新组织问题，或提出更有效的解法；有清晰且有意义的差异就值得继续探索。想法尚不成熟时，必须指出可怎样发展、完善或深化，以及如何检验新增价值；近邻用于学习和定位差异，不能变成必须完全没有先例的准入门槛。跨领域成熟方法的合理适配同样适用。
- 全流程研究覆盖输入、时序、关联、融合与输出。在作者或统一全场协议下优先评估关联、四属性融合与恢复的精度，计算速度作为次要代价。按场景、共享 A 组件、覆盖和尾部同时报告。原文报告、可核复现和 MTAD 适配分别说明。
- 近期目标与去留以研究状态为准；无增量且无新依据即关闭当前配方，不为沉没成本加步/seed/模块。单次失败不否定整类方法，内部对照或失效适配不能冒充可信同行。
- 用户要求的完整契约可作为既有文档中的必要字段引用，不建平行包目录或审批框架。历史实验缺事先Idea如实标记，不倒填预注册、不重跑凑流程。

## 执行与证据

- 用户授权本地研究决策、开发、必要核验及commit/push，不逐轮请批。新实验先定具体目的、输入、训练量、终点、停止条件，再发布独立READY；旧草案不是授权。
- 服务器负责执行和回传，最多四单卡、现场FIFO、兼容设备可共卡，不碰他人进程。活动checkout/config/runs冻结，新任务新目录、一次尝试，失败保全不自动重试。
- 本地不SSH值守、不建守护、不跨聊天/外部发消息。按[服务器规则](docs/server_autonomy.md)托管；墙时只建议，报告进度，不自动加训练。push不等于已启动；已创建的跟进安排与终止范围只在研究状态维护。
- 核真实命令/退出、配置、输入和数组/指标，Git仅历史定位，不设SHA/hash/fingerprint准入。保护他人修改、不强推，不覆盖原失败产物。
- [数据约定](docs/data_contract.md)与[论文指标](docs/mtad_data_protocols.md)是数据/单位/划分/评价的唯一规则入口。T_test封存，不删难例、不拼不同人口/单模块冠军；全人口、覆盖/重复、尾部与场景/组件并报，不用ME冒充MAE。
- 自建模拟只做必要软件排错，不能认证作者复现、MTAD成绩或同行资格；不再扩建模拟训练前置链。

- 当前入口写当前事实；结案结果写[历史摘要](docs/history/README.md)，详细来源按需查看。总结后可删除旧交接、重复产物、专用工具/测试/配置，从Git按单文件恢复；不另造archive树。
- 删除代码先查调用/导入/权重加载；仍被生产引用的旧名模块保留。整理不得改变模型数值、102等活动合同，或删除数据、真实权重、服务器runs、未审结果。
- 测试只核本次会破坏的链路；不为测试数扩建防御框架，不重复全数据扫描、诊断或成本测量。
- 文献与独有阅读证据保留在资料库；未筛设计不放在当前入口。没有明确待办时结束，不制造任务。
