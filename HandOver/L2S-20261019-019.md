## 服务器要做什么

1. 同步main并保护修改；新建本方S2L-019/RUNNING。使用既有Python，不重建环境或重跑全仓测试。
2. 核`systemd-run --version`、`systemctl --user`可访问和`loginctl show-user 当前UID --property=Linger --value`。Linger须为yes；在现有账户权限内可配置本用户的linger并记录前后值。没有权限或用户管理器不可用则回BLOCKED，列出真实缺项；不自动改成session/nohup冒充解决了runtime回收。
3. 从主仓根执行下列一次命令。它不导入torch、不开GPU、不给真实训练授权：

```bash
task_repo=$(pwd -P)
task_python=/home/wangguangjie/djs/mtad-field-20261016/bin/python
task_record="$task_repo/runs/PERSISTENCE-20261019-019-attempt-1"
"$task_python" tools/experiments/launch_detached.py \
 --cwd "$task_repo" --record-dir "$task_record" \
 --max-seconds 30 --grace-seconds 3 --env CUDA_VISIBLE_DEVICES= \
 -- "$task_python" -c 'import json,os,sys,time; from pathlib import Path; r=Path(sys.argv[1]); p=Path("/proc/self/cgroup"); (r/"probe-start.json").write_text(json.dumps({"pid":os.getpid(),"parent_pid":os.getppid(),"cgroup":p.read_text() if p.exists() else None})); time.sleep(5); (r/"payload-survived.txt").write_text("finished after submitting launcher exited\n"); print("CPU payload completed")' "$task_record"
```

启动返回0只表示提交成功。读取`launch.json`的unit，记录`systemctl --user show <unit>`中的MainPID/ControlGroup/ActiveState/SubState/Result/ExecMainCode/ExecMainStatus与当前AI任务cgroup。服务应是独立的`.service`，由用户服务管理器托管，不能是AI原会话scope/进程树。若任务已正常退出，部分systemd字段可能已卸载，保留实际输出并用probe-start中的cgroup核所属unit，不补值。

4. launcher返回后无需让AI保持长时间阻塞。约10秒后或下次重连读取同一record：`status.json`应COMPLETED、returncode0、timed_out=false，`exit_code.txt=0`，`payload-survived.txt`与stdout存在。失败保存原件，不重启；若status缺终态/RUNNING而unit已失败，取systemd Result/ExecMainStatus，不编造模型退出码。失败unit在取证前不reset-failed。

不要求故意重启整个AI运行时来测试，不终止其他会话。区分证据层级：本轮可核实“提交父进程已退出、任务由独立服务托管并写出结果”；若没有真实跨过AI runtime重启，不能宣称已实测该故障。正式训练在此机制下也不依赖AI前台子进程。
